## 0. 용어 먼저 정리 (피드백 1·6 답변)

사장님 눈높이 기준으로 앱의 동사를 통일한다. **화면 문구도 이 표를 따른다.**

| 용어 | 뜻 | 한 줄 설명 |
|---|---|---|
| **주문 확정** | 거래처(파는 곳)가 보낸 발주를 **우리 판매 장부에 저장**하는 것 | "가람식당이 시킨 것 기록 완료" — 매입처와는 무관 |
| **매입처 발주** | 우리가 사 오는 곳(매입처)에 보낼 **구매 요청 문장**을 만들어 복사·전송하는 것 | "야채매입처에 카톡 보낼 문장 만들기" |
| **발주 보냄 체크** (신규 개념) | 매입처별 문장을 실제로 보냈다고 표시하는 것 | 1차 보강: 화면 체크만(저장 안 됨) → 2차: DB 기록 |
| **거래명세서** | **우리 → 거래처** 판매 서류 (배송 갈 때 끊어주는 것) | 오더모아가 만들어주는 서류 |
| **매입처 쪽 명세서** | **매입처 → 우리** 서류. 매입처가 물건 보낼 때 발행 | **우리가 만드는 게 아님.** 오더모아 1차는 "보낸 발주 문장"까지만. 2차에서 발주 이력·입고 확인·매입 기록으로 확장 |

> 비개발자 설명(피드백 6): 거래명세서는 "판 사람"이 끊어주는 서류입니다. 우리가 거래처에 팔 때는 **우리가** 끊고(오더모아가 함), 매입처가 우리에게 팔 때는 **매입처가** 끊습니다. 그래서 매입처 발주에는 우리 쪽 명세서가 필요 없고, 보낸 발주 문장과 (나중에) 보냄/입고 기록만 있으면 됩니다.

**주문 확정 ↔ 매입처 발주 분리(피드백 1)**: 이미 데이터 구조상 분리되어 있음(주문 확정=orders 저장, 매입처 발주=합산표 위 표시 로직). 헷갈림은 **화면 문구 문제** → 아래 F1에서 문구만 보정한다. 새 데이터 개념 추가 없음.

## 2. 항목별 UX 설계안

### F1. 용어/안내 문구 (1차 즉시 — 문구만)

- 파싱 확인 화면의 "주문 확정" 버튼 아래 한 줄: `확정하면 이 거래처의 판매 주문으로 저장됩니다. 매입처 발주는 '품목별 합산표'에서 따로 합니다.`
- 합산표 상단 설명 보정: `여러 거래처 주문을 품목별로 합쳤습니다. 아래에서 품목을 체크하면 매입처에 보낼 발주 문장이 만들어집니다. (여기서 체크해도 판매 주문은 바뀌지 않습니다)`
- 주문 목록 화면 제목 옆 작은 설명: `저장된 판매 주문 (거래처가 시킨 것)`
- 구현: `page.tsx` 문구 수정만. 테스트 영향 없음.

### F2. 매입처 발주 문장 템플릿 (1차 즉시)

**출력 형식 (개별 매입처 복사 시):**
```
오더모아상사입니다
발주 품목입니다
1. 콩나물 3박스
2. 두부 8판
3. 식용유 2통
```

**전체 복사 시** (여러 매입처 구분 필요):
```
[야채매입처]
오더모아상사입니다
발주 품목입니다
1. 깐양파 2망
...

[두부콩나물매입처]
오더모아상사입니다
...
```

설계 결정:
- **회사명 소스**: DB 모드 = `session.companyName`(ordermoa_companies.name), 데모 모드 = `sampleCompany.name`. page.tsx가 이미 둘 다 가지고 있음 → `formatSupplierPurchaseText(sections, { companyName })` 파라미터로 주입.
- **개별 복사에는 `[매입처명]` 헤더를 넣지 않는다** — 받는 매입처 입장에선 자기 이름이 불필요. 화면 카드 제목으로만 표시.
- **1차 = 고정 기본 템플릿**(위 형식 하드코딩). "템플릿을 설정에서 수정"은 **2차**(설정 저장이 필요해 companies 컬럼 or settings 테이블 → DB 변경이라 미룸).
- 구현: `lib/aggregate.ts`의 `formatSupplierPurchaseText`(+ 개별 섹션용 함수) 수정 — **순수 함수라 단위 테스트로 형식 고정**. `page.tsx`에서 companyName 전달.

### F3. 매입처별 연한 색 구분 (1차 즉시)

- **고정 파스텔 팔레트 8색**(채도 낮음, 업무 톤: 연회색빛 파랑/초록/살구/보라 등)을 두고, 매입처 이름 해시로 색 배정 → 같은 매입처는 항상 같은 색.
- 표시 위치: 합산표 **매입처 셀 배경(연하게)** + 매입처별 발주 카드의 **왼쪽 3px 보더**. 행 전체 칠은 과함 — 셀만.
- 접근성: 색은 보조. **매입처 이름 텍스트는 항상 유지**(색만으로 의미 전달 금지).
- 인쇄: `@media print`에서 배경색 제거(흑백 프린터 대비), 텍스트 그대로.
- 모바일(390px): 셀 배경만 유지, 보더 무관.
- 구현: 순수 함수 `supplierColor(name): string`(lib, 테스트 가능) + `globals.css` 팔레트 클래스. DB 변경 없음.

### F4. 발주 누락 검수 (핵심 최소 = 1차 즉시)

**1차 즉시 (3가지만):**
1. **카운터 줄** — 발주 문장 영역 상단에 항상 표시:
   `발주 대상 12개 품목 · 문장에 담음 9개 · 안 담음 3개 · 매입처 미지정 1개`
2. **복사 전 경고** — "안 담음" 품목이 있는 상태에서 복사 버튼을 누르면:
   `아직 문장에 안 담은 품목이 3개 있습니다. 그래도 복사할까요?` (확인/취소) — 차단이 아니라 확인.
3. **매입처 미지정 경고 뱃지** — 합산표에서 매입처 미지정 품목의 매입처 셀에 노란 "미지정" 뱃지(색+텍스트).

**1차 보강:**
- "안 담은 품목만 보기" 필터 토글 (합산표 행 필터)
- 매입처 카드 제목에 `(품목 3개)` 카운트

**2차 (지금 안 함):**
- "오늘 발주 누락 위험" 대시보드 카드, 거래처별 기여 내역 대조, 발주 이력 기반 검수 (F8과 함께)

구현: 전부 화면 상태 파생값(체크셋 vs 합산 rows) — 순수 계산 함수 1개(`buildPurchaseChecklistSummary`) + 테스트. DB 변경 없음.

### F5. 발주 보냄 체크 (1차 보강 — 화면만)

- 매입처 카드마다 `보냄 ✓` 토글 버튼. 누르면 카드가 연회색 처리 + "보냄" 뱃지.
- **명시 라벨 필수**: `보냄 표시는 이 화면에서만 유지됩니다(새로고침 시 초기화)` — 저장되는 척하는 반쪽 기능 금지(헌장 원칙).
- DB 저장(발주 이력 테이블)은 **2차 F8**. 그때 이 토글이 자연스럽게 이력 기록으로 승격됨.

### F6. 매입처 관리 화면 — W07 (1차 보강)

- **UI 패턴**: `customer-management-view.tsx`를 그대로 복제·치환한 `supplier-management-view.tsx` — 좌측 목록(검색)+우측 폼(이름/메모), 추가/수정/보관. 마지막 1개 보관 차단 가드는 불필요(매입처 0개여도 앱 동작 — "매입처 미지정"으로 흘러감).
- **W06/W07 역할 분담**:
  - W07(매입처 관리) = 매입처 자체 CRUD만.
  - **품목별 기본 매입처 지정은 W03(품목·별칭 관리)에서** — 품목 폼에 매입처 드롭다운 한 칸. 품목을 고치는 김에 매입처를 고르는 게 동선상 자연스러움.
- **이름 변경 반영**: DB 모드는 품목이 매입처를 id(FK)로 참조하므로 이름 바꾸면 합산표/발주 문장에 자동 반영. 데모 모드는 suppliers 상태 갱신 시 products의 `purchaseSupplierName`도 함께 갱신 필요(주의 지점).
- **보관 주의**: 보관된 매입처를 참조하는 품목은 그대로 둔다(발주 문장에 이름 유지 + "보관됨" 표시). 같은 이름 재등록은 unique 충돌 → **보관 해제(복원) 버튼 포함**.
- store: `supplier-store.ts` (customer-store 패턴 복제: normalize/validate/insert/update/archive/unarchive + 테스트).

### F7. 거래명세서 하단 1차 보정 (1차 즉시 — 작게)

**지금 바로 (1차 즉시):**
- 하단 마무리 블록 추가: 합계 행 아래에
  - `공급가 합계 ₩000,000 (부가세 미포함 — 1차는 공급가만 표시)` 문구 위치 고정
  - **인수자 확인 한 줄**: `인수자: ____________ (서명)` + 비고 한 줄
- 빈 행 채움 개수를 A4 기준으로 재조정(현 10행 → 인쇄 미리보기로 확인하며 조정)
- 검증: 브라우저 인쇄 미리보기에서 A4 1장, 품목 3개/10개 두 케이스 확인.

**1.5차로 미룸 (기존 W14, delivery-note-print-spec.md 기준):**
- 공급자/거래처 정보 블록(사업자번호 등), 규격 컬럼, 금액 한글 표기, 보존용/거래처용 2부 출력, 양식 커스텀.

### F8. 발주 이력·입고·매입 기록 (2차 — 설계 여지만)

## 5. 위험 / 헷갈리는 지점

- **용어 혼용**: "발주"가 ①거래처가 우리에게 시킴 ②우리가 매입처에 시킴 두 방향으로 쓰임 → 화면에서는 "발주 붙여넣기(받은 것)" / "매입처 발주(보내는 것)"로 구분 표기 유지.
- **데모 모드 이름 동기화**: 매입처 이름 변경 시 데모 모드는 products 상태의 `purchaseSupplierName` 수동 갱신 필요 — 빠뜨리면 화면 불일치.
- **보관 매입처 재등록**: unique(company_id,name) 충돌 → 복원 기능으로 해결(F6에 포함).
- **보냄 체크 착시**: 저장 안 되는 1차 보강 단계에서 반드시 "화면에서만 유지" 라벨.
- **인쇄 색상**: 배경색은 프린터마다 다르게 나옴 → print에서 제거가 안전.
- **템플릿 회사명**: 회사명이 비어있을 수 있음(데모/미설정) → `회사명 없음이면 인사 줄 생략` 규칙.
