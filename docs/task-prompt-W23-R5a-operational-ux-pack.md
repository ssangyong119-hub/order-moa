## 구현 상세

### A. 가격 입력 UX

대상은 파싱 확인의 판매가 입력, 가격 마감의 최종 판매가 입력, 단가 관리의 거래처별 단가 입력이다.

- focus되면 `select()`로 현재 텍스트 전체선택.
- Enter면 다음 금액 입력으로 이동하고 이동한 값도 전체선택. 마지막 입력이면 기존 저장/흐름을 깨지 말 것.
- blur 시 양의 정수/0 KRW 표시로 정규화하여 `05` 같은 선행 0 제거.
- 빈 값·음수·NaN·Infinity 처리와 기존 저장 차단은 기존 패턴을 존중.
- 공통 훅/작은 헬퍼가 중복을 실제로 줄일 때만 추출. 과도한 UI 리팩터 금지.

### B. 단가 관리 표시 정합성

현재 화면은 `customer_prices`만 보여 기본 출고단가가 있는 품목도 전부 미등록처럼 보인다. 각 행에 아래를 명확히 표시한다.

- 거래처별 단가: 있으면 현재 단가, 없으면 `거래처별 미등록`.
- 기본 출고단가: `products.baseSalePrice`가 있으면 금액, 없으면 `없음`.
- 현재 적용 단가: 거래처별 단가 우선, 없으면 기본 출고단가, 둘 다 없으면 `미등록`.
- 기본 출고단가가 있을 때 노란 `미등록`을 쓰지 말고 `기본 단가 적용 중` 상태를 사용.
- 이 화면의 입력·저장은 계속 거래처별 예외 단가만 바꾼다. 기본 출고단가 수정 기능을 이 화면에 추가하지 말고, 기존 품목·별칭 관리 흐름을 안내로 연결할 수 있다.

### C. 매입처 발주 문장

`aggregate.ts`의 순수 텍스트 생성 로직부터 테스트로 고친다.

- 기본 문장 첫 줄에 합산표 적용 날짜(`YYYY-MM-DD`)를 넣는다. 합산표가 전체 보기처럼 날짜가 여러 개인 경우 오늘 날짜를 제안값으로 쓴다.
- 둘째 줄은 `<회사명>입니다 발주 품목입니다`.
- 매입처별 문장과 전체 문장은 편집 가능한 textarea로 바꾼다.
- 체크박스/매입처 배정이 바뀌었다고 사용자의 문장을 자동 덮어쓰지 않는다. `문장 다시 만들기` 버튼으로만 새로 생성하고, 편집 이력이 있으면 확인을 받는다.
- `이 매입처만 복사` 및 전체 복사 동작은 수정된 textarea 값을 복사한다.
- 이번 세션의 편집본을 DB·로컬스토리지·템플릿 설정에 저장하지 않는다.

### D. 이번 발주만 매입처 변경

- 합산표의 각 행에서 현재 매입처명/`미지정` 배지를 눌러 활성 매입처 select를 연다.
- 선택은 `productId + unit` 기준 행의 화면 상태 override다. 즉시 `products.purchase_supplier_id`를 바꾸지 않는다.
- override가 바뀌면 합산표 매입처별 묶음·누락 카운터·발주 문장이 즉시 재계산되어야 한다.
- `앞으로 기본 매입처로도 저장`은 별도 명령과 확인을 통해서만 제품 기본값을 갱신한다. 이번 작업에서 이 명령을 만들기 어렵다면 임시 override만 먼저 만들고, 기본값 저장 버튼은 추가하지 말고 보고한다.
- 보관된 매입처는 선택지에서 제외한다.
