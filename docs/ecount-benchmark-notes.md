# ECOUNT 화면 벤치마킹 메모 — 2026-07-09

참고 이미지: `docs/references/ecount-screenshots/ecount-product-list1.png` ~ `ecount-product-list6.png`

## 전제

- 이미지는 사용자가 민감한 거래처명/상호명을 가린 참고 화면이다.
- 화면의 품목코드는 품목 마스터 식별용 숫자라 민감정보로 보지 않는다.
- 오더모아는 전체 ERP가 아니라 도소매/식당납품용 좁은 MVP이므로, 회계/세금/전표 전체 흐름은 벤치마킹만 하고 즉시 구현 범위에 넣지 않는다.

## 화면별 관찰

### 거래처 리스트

- 거래처를 코드/명칭/대표자/전화/모바일/사용 여부로 관리한다.
- 오더모아 적용 가능성:
  - 이미 거래처 관리는 있으므로, 단기 구현보다는 검색/보관/복원 UX 개선 참고.
  - 거래처 코드가 필요해지면 `externalCode` 같은 외부 코드 필드로 분리하는 방향이 적절하다.
- 후순위:
  - 전화/모바일/주소/사업자번호 고도화는 MVP 이후.

### 매출전표 입력

- 전표일자, 부가세유형, 거래처, 공급가액, 부가세, 세부내역, 적요, 매출계정, 입금계좌, 첨부를 한 화면에서 입력한다.
- 오더모아 적용 가능성:
  - 전표/회계 입력 흐름은 현재 MVP 범위 밖.
  - 다만 거래명세서/주문 상세에서 "발주 원문", "주문 메모", "첨부" 같은 보조 정보 영역은 장기 참고 가능.
- 제외:
  - 전자세금계산서, 계정과목, 입금계좌, 회계 반영은 후순위/제외 원칙 유지.

### 판매조회

- 날짜별 주문/판매 목록에서 거래처, 품목명 요약, 금액합계, 창고, 인쇄, 불러온 전표 조회를 제공한다.
- 오더모아 적용 가능성:
  - 주문 목록의 날짜 필터, 거래처 필터, 인쇄/명세서 보기 흐름은 이미 방향이 맞다.
  - "품목명 요약 외 N건" 표시 방식은 주문 목록 밀도를 높일 때 참고할 만하다.
- 주의:
  - 판매조회 export는 품목별 단가 기준정보로는 부족하다. 품목 마스터/단가 마스터 export를 우선 사용한다.

### 품목등록 리스트

- 품목코드, 품목명, 품목구분, 규격정보, 품목그룹, 검색창내용, 사용 여부, 파일관리, Excel export가 있다.
- 오더모아 적용 가능성:
  - 품목명/규격/단위 분리는 W21 import 미리보기의 핵심 필드로 둔다.
  - 품목코드는 import 중복 매칭에 유용하므로 `sourceCode` 후보로 기록한다.
  - 사용 여부는 오더모아의 보관/복원 상태로 매핑 가능하다.
  - 파일관리는 MVP 밖.

### 품목등록 상세

- 기본 탭에서 품목코드, 품목명, 규격, 단위, 부가세율, 품목구분, 세트여부, 재고수량관리, 입고단가, 출고단가를 관리한다.
- 오더모아 적용 가능성:
  - `출고단가`는 기본 판매단가 후보.
  - `입고단가`는 매입가/예상마진 참고값 후보.
  - 부가세율은 현재 "VAT 미적용/부가세 없음(1차)" 원칙 때문에 즉시 확장하지 않는다.
  - 재고수량관리는 재고 ERP화로 이어질 수 있어 후순위.

### 품목별단가

- 품목코드, 품목명, 규격, 단위, 출고단가, 입고단가, 단가A~단가J가 한 표에 있다.
- 오더모아 적용 가능성:
  - W20 실제 엑셀 기준정보 추출의 최우선 원본.
  - W21 import 미리보기에서 `품목코드/품목명/규격/단위/출고단가/입고단가`를 먼저 매핑한다.
  - 단가A~J는 Phase 3의 "기본단가 + 거래처별 예외/가격그룹" 설계 참고로만 기록한다.

## 기능 후보 정리

### 바로 참고할 것

- 품목코드 보관: import 중복 매칭용 `sourceCode` 후보.
- 품목명/규격/단위 분리: 다단위 이전에도 import 미리보기에서는 분리 표시.
- 입고단가/출고단가 구분: 출고단가=판매 기준, 입고단가=매입/마진 참고.
- 사용 여부 매핑: 사용 안 함 품목은 보관 후보.
- Excel export/import 흐름: 기준정보는 파일 기반 검수 후 반영.

### 다음 세션(W21) 후보

- 품목 마스터/단가 마스터 파일을 읽는 import 미리보기.
- 중복 후보 표시: 품목코드 우선, 없으면 품목명+규격+단위.
- 카테고리 자동 분류와 사용자 수정.
- 대표 판매단가/매입단가 반올림 표시.
- 적용 전 "추가/수정/보관 후보" 요약.

### Phase 3 이후

- 품목별 여러 단위 구조.
- 기본 판매단가 + 거래처별 예외 단가.
- 가격 그룹(단가A~J) 또는 거래처 등급.
- 입고단가 기반 예상마진 고도화.

### 제외/후순위

- 전자세금계산서 발행.
- 회계 전표/계정과목/입금계좌.
- 재고수량관리/재고평가.
- 파일관리/첨부 고도화.
- 이카운트 직접 연동.

## 설계 메모

- **구현 참고는 품목등록/품목별단가 화면 중심으로 좁힌다.** 거래처리스트·매출전표·판매조회는 회계/전표 성격이 커 MVP 밖(관찰만). W20/W21 기준정보 추출·import는 품목등록(품목명·규격·단위·사용여부)과 품목별단가(출고단가·입고단가·품목코드)만 원본으로 쓴다.
- 이카운트 화면은 넓은 ERP 구조지만, 오더모아는 "카톡/문자 발주 → 정제 → 단가 적용 → 주문 확정 → 합산표/명세서" 흐름을 유지한다.
- 벤치마킹 결과는 품목·단가 기준정보 import와 단가 설계에만 좁게 반영한다.
- 과거 주문 금액은 계속 `order_items.unit_price` 스냅샷으로 유지하고, 품목/단가 마스터 변경으로 재계산하지 않는다.
