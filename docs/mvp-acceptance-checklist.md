# 오더모아 MVP 검수 체크리스트

작성일: 2026-06-29
근거: `docs/requirements-definition.md`, `docs/function-specification.md`(§11 MVP 완료 기준, §13/§14 확정값)

> 목적: 오더모아 1차 웹 MVP가 "완료됐다"고 판단하기 위한 검수 기준. 각 항목은 체크박스로 검수한다. 새 기능 추가 없이, 확정된 범위 기준으로만 점검한다.

---

## 1. 제품 범위 체크

- [ ] 제품 방향이 "중간 납품업자 특화 웹 ERP"로 유지된다(완성형 범용 ERP 아님).
- [ ] 1차 핵심 가치(카톡/문자 발주 취합 → 거래처별 주문표 → 품목별 총 발주표 → 단가 → 거래명세서)가 동작한다.
- [ ] 1차 범위를 넘는 기능을 임의로 추가하지 않았다.
- [ ] **MVP가 완성형 ERP가 아니라 영업/검증용 MVP로 정의**돼 있다.
- [ ] 실제 사용자가 직접 모든 초기 데이터를 입력하지 않아도 시연 가능하다.
- [ ] **초기 세팅 대행 전제**가 문서/시나리오에 반영돼 있다.

## 2. 기능 체크 (F1~F13)

- [ ] 로그인 가능 (F1)
- [ ] 회사/사업장 생성 가능 (F2)
- [ ] 거래처 등록/수정 가능 (F3)
- [ ] 품목 등록/수정 가능 (F4)
- [ ] 품목 별칭 등록 가능 (F5)
- [ ] 거래처별 단가 등록 가능 (F6)
- [ ] **샘플 발주 10건 입력 가능** (F7~F10)
- [ ] **거래처별 주문 저장 가능** (F10)
- [ ] **품목별 합산표 생성 가능** (F11)
- [ ] 거래처별 주문표 생성 가능 (F12)
- [ ] **거래처별 단가 자동 적용 가능** (F6/F10)
- [ ] **샘플 데이터로 첫 화면/주요 흐름을 시연**할 수 있다.
- [ ] 샘플 데이터에는 거래처·품목·별칭·단가·발주 예시가 포함된다.
- [ ] 샘플 데이터에는 **개인정보/실거래처명이 포함되지 않는다**.
- [ ] 거래처/품목/단가를 **빠르게 등록**할 수 있는 흐름이 있다.

## 3. 데이터 체크

- [ ] **`order_items.product_id`는 확정 주문에서 필수**(NOT NULL)다.
- [ ] 파싱 후보/draft 라인은 DB에 영구 저장되지 않는다(화면 + `order_imports.raw_text`).
- [ ] **`raw_text` 저장 및 삭제가 가능**하다(기본 저장 ON).
- [ ] **`raw_text` 삭제 후에도 확정 주문(orders/order_items)은 유지**된다.
- [ ] `order_imports.customer_id`는 NOT NULL이다(붙여넣기 전 거래처 선택 필수).
- [ ] 라인 금액 = `round(quantity × unit_price)`, 합계 = 라인 금액의 합(합산 후 반올림 없음).
- [ ] 금액은 KRW integer, 수량은 numeric으로 저장된다.

## 4. DB / RLS 체크

- [ ] **회사별 데이터 격리**가 적용된다(모든 업무 테이블 `company_id`).
- [ ] 모든 업무 테이블에 RLS가 활성화돼 있다.
- [ ] **A회사 사용자가 B회사 데이터에 접근할 수 없다**(select/insert/update 차단).
- [ ] 공개 API에서 `company_id`를 바꿔도 차단된다.
- [ ] **service role key가 클라이언트에 노출되지 않는다**.
- [ ] `.env`/환경변수가 Git에 커밋되지 않는다.

## 5. 화면 / UX 체크 (S1~S11)

- [ ] 로그인·회사 생성·대시보드 진입 흐름이 동작한다.
- [ ] 거래처/품목/단가 화면에서 등록·수정이 가능하다.
- [ ] 발주 붙여넣기 → 파싱 결과 확인 → 주문 저장 흐름이 자연스럽다.
- [ ] 주요 화면이 모바일에서 사용 가능하다(반응형).
- [ ] ERP 용어 부담 없이 현장 용어 위주로 표시된다.
- [ ] 빈 상태/오류 상태 안내가 제공된다.

## 6. 발주 파싱 체크 (F8/F9)

- [ ] 시스템은 후보만 제안하고 사용자가 최종 확정한다(완전 자동 확정 없음).
- [ ] **미매칭 품목 라인이 남으면 주문 확정이 차단된다.**
- [ ] **수량 불확실 라인이 남으면 주문 확정이 차단된다.**
- [ ] 미매칭 품목은 경고(빨강) 상태로 표시된다.
- [ ] 미매칭 품목을 품목 별칭으로 즉석 등록하고 재매칭할 수 있다.

## 7. 거래명세서 체크 (F13)

- [ ] **거래명세서 미리보기가 가능**하다.
- [ ] 거래명세서는 공급가 합계만 표시한다.
- [ ] **거래명세서 VAT 계산이 없다**(1차).
- [ ] 인쇄(브라우저 인쇄)가 가능하다.
- [ ] **거래명세서 PDF 생성은 후순위**다(1차 미구현 허용).
- [ ] `delivery_notes` 저장/`note_number` 자동 채번은 후순위/선택임이 유지된다.

## 8. 미수금 수동 체크

- [ ] 미수금은 주문/거래명세서 기준 수동 status 체크만 제공한다(unpaid/partial/paid).
- [ ] 입금 자동 매칭은 없다(2차).
- [ ] 오래된 미수금 알림은 없다(2차).

## 9. 제외 기능 체크

- [ ] **카톡 자동읽기 없음**
- [ ] **OCR 없음**
- [ ] **홈택스 세금계산서 직접 발행 없음**
- [ ] **은행 입금 자동 매칭 없음**
- [ ] **이카운트 연동 없음**
- [ ] 전체 재고 ERP 수준 구현 없음

## 10. 사용자 테스트 체크

- [ ] **실제 납품업자 1~2명이 자기 발주 예시로 테스트** 가능하다.
- [ ] "다시 써볼 만하다" 수준의 피드백을 받을 수 있다.
- [ ] 발주 취합/합산표가 실제 업무에 쓸 만한지 확인할 수 있다.
- [ ] **실제 납품업자에게 자기 카톡/문자 발주 예시로 테스트**받을 수 있다.
- [ ] 사용자가 **"다시 써보고 싶다"**는 반응을 보이는지 확인한다.
- [ ] **월 3만 원 이상 지불 가치**가 있는지 질문한다.
- [ ] **초기 세팅을 맡겨도 써볼 의향**이 있는지 확인한다.

## 11. 문서 / Git 체크

- [ ] **설문 5건 한계가 문서에 유지**된다(과장 없음).
- [ ] 요구사항정의서·기능정의서·DB 스키마/RLS 문서가 일관된다(충돌 표현 없음).
- [ ] 확정값(C1~C5, A~D)이 문서에 반영돼 있다.
- [ ] 작업 단위별 커밋/푸시가 정리돼 있고 미커밋 변경이 보고된다.
