# 오더모아 웹 MVP 로드맵

작성일: 2026-06-06

## 1. 전체 일정 요약

현실적인 일정:

- 1주: 웹 MVP 설계와 기술 스파이크
- 2주: 핵심 CRUD와 발주 붙여넣기/합산표
- 4주: 실제 사용자 테스트 가능한 웹 MVP
- 8주: 미수금/단가이력/거래명세서/초기 유료 검증

전제:

- 개발자 1명 기준
- 평일 1~3시간, 주말 추가 작업 가능 기준
- 완성형 ERP가 아니라 사용자 검증용 MVP 기준

## 2. 1주차: 설계와 기술 검증

목표:

- 웹 전환이 기술적으로 가능한지 확인한다.
- Supabase Auth/RLS와 Next.js 기본 구조를 검증한다.

작업:

- Next.js 프로젝트 생성
- Supabase 프로젝트 생성
- 로그인 구현
- 회사 생성 테이블 구현
- 거래처 샘플 테이블 구현
- RLS 정책 테스트
- 기존 로컬 MVP 화면 흐름 재검토

산출물:

- 웹 프로젝트 골격
- 로그인 화면
- 회사별 거래처 조회 검증
- RLS 테스트 결과

성공 기준:

- A 회사 사용자가 B 회사 거래처를 볼 수 없다.
- 로그인한 사용자만 앱에 접근한다.
- 로컬 MVP 데이터를 웹 DB 구조로 옮길 수 있다.

## 3. 2주차: 핵심 업무 흐름

목표:

- 거래처/품목/단가/발주/합산표 흐름을 웹에서 구현한다.

작업:

- 거래처 CRUD
- 품목 CRUD
- 품목 별칭 CRUD
- 거래처별 단가 CRUD
- 카톡/문자 발주 붙여넣기 화면
- 규칙 기반 파싱
- 주문 확인/수정 화면
- 주문 저장
- 품목별 합산표

산출물:

- 실제 사용자가 발주를 넣어볼 수 있는 웹 화면
- 품목별 총 발주표

성공 기준:

- 샘플 발주 10건을 넣고 합산표를 만들 수 있다.
- 품목 별칭으로 1차 매칭이 가능하다.
- 사용자가 파싱 결과를 수정할 수 있다.

## 4. 3~4주차: 업무 검증 MVP

목표:

- 실제 사용자에게 보여줄 수 있는 MVP를 만든다.

작업:

- 거래명세서 미리보기
- 거래명세서 인쇄/다운로드 준비
- CSV/Excel 내보내기
- 모바일 화면 개선
- 단가 변경 이력
- 기본 미수금 수동 체크
- 테스트 데이터 초기화/샘플 생성
- 사용자 피드백 수집 양식

산출물:

- 배포 URL
- 테스트 계정
- 사용자 테스트 시나리오

성공 기준:

- 실제 납품업자 1~2명이 자기 발주 예시로 테스트한다.
- 발주 취합/합산표 기능을 다시 써보겠다는 피드백이 나온다.
- 어떤 기능이 빠져서 유료 사용이 어려운지 확인한다.

## 5. 5~8주차: 유료 검증 후보

목표:

- 월 사용료를 받을 수 있는 수준의 최소 기능을 확인한다.

작업:

- 미수금/입금 관리
- 오래된 미수금 알림
- 거래처별 월 정산표
- 매입가/판매가/마진 계산
- 세금계산서 발행 금액 부족/초과 표시
- 직원 계정/권한
- 백업/내보내기 개선

산출물:

- 베타 버전
- 가격 가설
- 유료 전환 인터뷰

성공 기준:

- 최소 1명이 월 3만~5만 원 지불 의사를 구체적으로 밝힌다.
- 기존 ERP를 보조하거나 일부 대체할 가치가 확인된다.

## 6. 에이전트/플러그인 활용 전략

Codex:

- 코드 구현
- 테스트 작성
- 문서 관리
- Git/GitHub 작업
- 로컬/웹 MVP 검증

Browser/Chrome:

- 로컬 웹 화면 검증
- 배포 URL 동작 확인
- 반응형 화면 캡처

Spreadsheets:

- 설문 결과 분석
- 엑셀 내보내기 포맷 검증
- 사용자 업무 데이터 샘플 분석

GitHub:

- 브랜치 관리
- PR/이슈 정리
- 회사/집 작업 동기화

Google Drive:

- 설문 결과
- 캡처 자료
- 통화 메모
- 기획 문서 보관

추후 가능:

- Documents: 제안서/사용자 인터뷰 문서 작성
- Presentations: 투자/지원사업/협업 제안 발표자료 작성

## 7. 리스크와 대응

리스크 1: 사용자가 품목/단가 초기 등록을 귀찮아함

대응:

- 엑셀 업로드 또는 샘플 템플릿 제공
- 자주 쓰는 품목부터 등록하게 유도

리스크 2: 발주 파싱 정확도가 낮음

대응:

- 완전 자동이 아니라 후보 표시
- 사람이 빠르게 수정하는 UI 제공

리스크 3: 기존 ERP 대체가 어려움

대응:

- 처음부터 대체를 강요하지 않는다.
- 발주 취합/합산표 보조 도구로 가치 검증
- 이후 미수금/정산으로 대체 범위 확대

리스크 4: 보안/개인정보 문제

대응:

- 회사별 데이터 격리
- RLS 우선 구현
- 첨부파일/OCR 후순위
