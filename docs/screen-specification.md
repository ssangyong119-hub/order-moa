작성일: 2026-06-29
작성 주체: Claude (단위 3 — 화면 설계)
근거 문서: `docs/requirements-definition.md`, `docs/function-specification.md`(F1~F13/S1~S11), `docs/mvp-validation-strategy.md`, `docs/mvp-acceptance-checklist.md`, `docs/db-schema-definition.md`, `docs/supabase-rls-policy.md`

> 본 문서는 1차 MVP 화면/흐름 설계 문서다. 코드·SQL·마이그레이션은 포함하지 않는다. 새 기능을 추가하지 않으며, 기능정의서의 F1~F13 범위 안에서 화면을 정리한다. 설문 5건 한계 전제는 유지된다.
>
> **번호 주의**: 본 문서의 화면 번호(S1~S14)는 Codex 단위3 지정값이며, 기능정의서의 S1~S11과 번호가 다르다. 각 화면에 기능정의서 기능(F#) 매핑을 함께 표기한다.

## 1. 화면 설계 개요

- **목적**: 사장님(납품업자)이 보게 될 화면과 이동 흐름을, 개발자뿐 아니라 비개발 기획자도 이해할 수 있게 정의한다.
- **1차 MVP 화면 전략**: "가입 후 알아서 쓰는 앱"이 아니라, **샘플 데이터와 초기 세팅으로 발주 붙여넣기 가치를 빠르게 보여주는 앱**.
- **영업/검증용 MVP 관점**: 완성형 ERP 화면(복잡한 메뉴 트리)을 만들지 않는다. "오늘 할 일" 중심 + 시연 흐름 우선.
- **사용자가 가장 먼저 느껴야 하는 가치**:

> **"카톡/문자 발주를 붙여넣으면 품목별 합산표가 나온다."**

- 용어 원칙: 현장 용어 우선("거래처/발주/총 발주표"), ERP 용어 회피("전표/계정/원장" 등 안 씀).

## 3. 핵심 사용자 흐름

### A. 첫 방문/시연 흐름 (영업 1순위)
로그인 → 회사 생성 → **샘플 데이터 불러오기** → 대시보드 → 발주 붙여넣기 → 파싱 확인 → **합산표 확인**

### B. 실제 세팅 대행 흐름 (우리가 대신 세팅)
로그인 → 회사 생성 → 거래처 등록 → 품목/별칭 등록 → 단가 등록 → **실제 발주 붙여넣기** → 합산표 확인

### C. 매일 사용하는 흐름
대시보드 → 발주 붙여넣기 → 파싱 수정 → 주문 저장 → 품목별 합산표 → 거래명세서 미리보기

### D. 사용자 테스트 흐름 (영업 현장)
샘플 또는 실제 데이터 준비 → **사장님 앞에서 발주 붙여넣기** → 합산표 확인 → "다시 쓸 의향/가격" 질문

```
[시연 핵심 경로]  대시보드 → S8 붙여넣기 → S9 확인 → S11 합산표   ← 여기서 "편한데?"가 나와야 함
```

## 4. 화면별 상세 설계

> 형식: 목적 / 주요 사용자 / 진입 경로 / 주요 UI / 사용자 행동 / 결과 / 빈 상태 / 오류 상태 / 모바일 / 연결 기능 / 연결 데이터 / 후순위·제외

### S1 로그인
- 목적: 인증된 사용자만 진입 / 사용자: 전체
- 진입 경로: 앱 첫 진입
- 주요 UI: 이메일 입력(또는 소셜 1종), 로그인 버튼, 한 줄 소개("카톡 발주를 붙여넣으면 총 발주표가 나옵니다")
- 행동: 인증 → 로그인
- 결과: 회사 있으면 S3, 없으면 S2
- 빈 상태: 입력 전 버튼 비활성
- 오류 상태: 인증 실패/네트워크 오류 메시지
- 모바일: 단일 컬럼, 큰 입력창
- 연결 기능: F1 / 연결 데이터: auth user
- 후순위·제외: 소셜 다중·비밀번호 자체구현 제외

### S2 회사 생성/선택
- 목적: 최초 회사 생성 또는 소속 회사 선택 / 사용자: 로그인 사용자
- 진입 경로: 로그인 후 회사 없음
- 주요 UI: 소속 회사 목록, "회사 만들기" 폼(상호 필수, 사업자번호 선택)
- 행동: 회사 생성/선택
- 결과: 회사 컨텍스트 설정 → S3. 생성은 회사+owner 멤버를 **한 번에 안전하게**(서버 트랜잭션/RPC, RLS 부트스트랩) 처리
- 빈 상태: 소속 회사 0 → 생성 폼만
- 오류 상태: 상호 누락, 생성 실패
- 모바일: 단일 컬럼
- 연결 기능: F2 / 연결 데이터: companies, company_members
- 후순위·제외: 직원 초대 2차

### S3 대시보드 (오늘 할 일)
- 목적: 오늘 발주/합산 진입점(메인) / 사용자: 회사 소속
- 진입 경로: 로그인·회사 선택 후 기본 화면
- 주요 UI: **[발주 붙여넣기]** 큰 버튼, **[샘플 데이터 시작]**, 오늘 주문 수, 오늘 품목별 합산표 바로가기, 거래처/품목/단가 빠른 등록 바로가기, 거래명세서 바로가기
- 행동: 주요 작업으로 이동
- 결과: 요약 카드 + 바로가기
- 빈 상태: "아직 등록된 데이터가 없습니다. 샘플 데이터로 먼저 흐름을 확인해보세요." + [샘플 데이터 시작]
- 오류 상태: 요약 로드 실패 재시도
- 모바일: 버튼 세로 스택, 합산표 바로가기 상단
- 연결 기능: F7/F11/F3~F6 / 연결 데이터: orders, order_items(집계)
- 후순위·제외: 매출 그래프/통계 위젯 제외(§5 참조)

### S4 샘플 데이터 시작
- 목적: 실제 데이터 없이도 핵심 흐름 시연 / 사용자: 회사 소속(영업 담당 포함)
- 진입 경로: 대시보드 빈 상태 / 대시보드 버튼
- 주요 UI: [샘플 데이터 시작] 버튼, 포함 데이터 설명(거래처·품목·별칭·단가·발주 예시), "개인정보/실거래처명 없음" 표시, 초기화/다시 만들기 주의
- 행동: 샘플 불러오기 → 대시보드/합산표로 유도
- 결과: 가명 샘플 데이터 적재 후 시연 가능 상태
- 빈 상태: 해당 없음(이 화면이 빈 상태 해소책)
- 오류 상태: 적재 실패 재시도
- 모바일: 단일 컬럼, 설명 카드
- 연결 기능: 샘플 데이터 생성(§2 단순화) / 연결 데이터: customers·products·product_aliases·customer_prices·order_imports(예시)
- 후순위·제외: 업종별 다중 템플릿 2차

### S5 거래처 관리
- 목적: 거래처 등록/수정/조회 / 사용자: 회사 소속
- 진입 경로: 대시보드 → 거래처
- 주요 UI: 목록(검색), 등록/수정 폼(상호 필수, 전화·주소·메모), 보관(archive)
- 행동: 추가/수정/보관
- 결과: 목록 갱신 + 토스트
- 빈 상태: "첫 거래처를 등록하거나, 샘플 데이터로 시작하세요."
- 오류 상태: 상호 누락, 동일 상호 중복 경고(차단 아님)
- 모바일: 목록 카드형, 폼 풀스크린
- 연결 기능: F3 / 연결 데이터: customers
- 후순위·제외: 엑셀 업로드 후순위(§11)

### S6 품목/별칭 관리
- 목적: 품목 + 파싱 매칭용 별칭 관리 / 사용자: 회사 소속
- 진입 경로: 대시보드 → 품목
- 주요 UI: 품목 목록, 등록/수정 폼(품목명·기본단위·과세구분), **별칭 다중 입력**("콩/콩나물박스")
- 행동: 품목·별칭 추가/수정/보관
- 결과: 목록 갱신
- 빈 상태: "첫 품목을 등록하거나 샘플로 시작하세요."
- 오류 상태: 품목명 누락, 중복 별칭 경고/차단
- 모바일: 별칭 칩 입력
- 연결 기능: F4·F5 / 연결 데이터: products, product_aliases
- 후순위·제외: 과세 계산 2차, 엑셀 업로드 후순위

### S7 단가 관리
- 목적: 거래처별 판매 단가 등록/수정 / 사용자: 회사 소속
- 진입 경로: 대시보드 → 단가 / 거래처 상세
- 주요 UI: 거래처 선택 → 품목별 입력 표(품목, **판매단가**, 적용일=메모성, **기준 매입단가(참고, 품목 공통), 예상 마진(선택 표시)**), 미등록 품목 표시
- 행동: 판매단가 입력/수정. 기준 매입단가가 있으면 **예상 마진 = (판매단가 − 기준 매입단가)** 자동 표시
- 결과: 저장 후 표 갱신
- 빈 상태: 단가 미등록 품목 강조
- 오류 상태: 단가 음수, 저장 실패
- 모바일: 행 단위 입력, 가로 스크롤
- 연결 기능: F6 (기준 매입단가는 F4 products) / 연결 데이터: customer_prices, products(base_purchase_price)
- 후순위·제외: 단가 변경 이력 2차. **예상 마진은 참고값**(매입단가 없으면 `-`), **정확한 회계 마진은 2차**

### S8 발주 붙여넣기
- 목적: 카톡/문자 원문 입력 후 파싱 시작 / 사용자: 회사 소속
- 진입 경로: 대시보드 [발주 붙여넣기]
- 주요 UI: 거래처 선택, **원문 textarea**, 예시 문구, [파싱] 버튼, 원문 길이 표시, raw_text 저장 안내 + 원문 삭제 가능 안내 + 민감정보 주의(§6)
- 행동: 거래처 선택 + 원문 붙여넣기 → 파싱
- 결과: S9로 파싱 후보 전달
- 빈 상태: textarea 비면 버튼 비활성, 예시 placeholder
- 오류 상태: 거래처 미선택, 길이 초과
- 모바일: textarea 충분히 크게, 붙여넣기 편의
- 연결 기능: F7 / 연결 데이터: order_imports(raw_text 기본 저장 ON)
- 후순위·제외: 카톡 자동읽기·OCR 제외

### S9 파싱 결과 확인/수정
- 목적: 파싱 후보를 사람이 확인·수정·확정 / 사용자: 회사 소속
- 진입 경로: S8 파싱 후
- 주요 UI: 라인별 표(원문 토막·매칭 품목·**수량·단위·단가(직접 입력)**·금액·상태), 미매칭(빨강)/수량 불확실(노랑)/단가 미등록(앰버) 경고, [별칭으로 등록], **단가 미등록 라인의 [이 단가 저장]**, [주문 확정](§7)
- 행동: 매칭/수량/단위/**단가 직접 수정**, 미매칭 해결, **단가 입력→저장(customer_prices)**, 확정
- 단가 수정/저장 UX(이카운트 벤치마크 반영):
  - 단가 칸은 **인라인 입력**(거래처별 자동 적용값을 덮어쓸 수 있음). 단가 변경 시 **금액 자동 재계산**(`round(수량×단가)`).
  - 단가 미등록(0원) 라인은 경고만이 아니라 **그 자리에서 단가 입력 + [이 단가 저장]** → 다음 주문부터 자동 적용. 저장 없이 이번 주문에만 적용도 가능.
- 결과: 확정 시 주문 저장 → S10/S3
- 빈 상태: 파싱 0줄 → 수동 행 추가
- 오류 상태: **미매칭/수량 불확실 라인 잔존 시 확정 차단**, 단가 음수 경고
- 모바일: 라인 카드형(좁은 화면에서 표 대체), **단가/수량은 모바일에서도 탭해서 수정 가능**(큰 터치 영역)
- 연결 기능: F8·F9 / 연결 데이터: order_imports, products, product_aliases, customer_prices(단가 저장 시 upsert)
- 후순위·제외: 자동 확정 없음(반자동 고정)

### S10 주문 목록(판매조회형) / 주문 상세 / 거래처별 주문표
- 목적: 저장된 주문 목록·조회·수정 + 거래처 단위 주문표 / 사용자: 회사 소속
- 진입 경로: S9 확정 후 / 대시보드 → 주문
- 주요 UI:
  - **주문 목록(이카운트 판매조회 벤치마크)**: 행마다 **날짜 / 거래처 / 품목요약 / 금액 / 상태 / [명세서] 버튼**. 날짜·거래처 필터. 행 클릭 → 주문 상세.
  - 주문 상세: 거래처·일자 헤더, 품목 라인, 합계, 수정/취소, [거래명세서 보기]
  - 거래처별 주문표 보기/CSV
- 행동: 목록에서 주문 찾기, 주문 수정·취소(soft), 명세서/주문표 이동
- 결과: 목록/갱신된 주문/주문표
- 빈 상태: 주문 없음 안내
- 오류 상태: 권한 외 접근 차단, 저장 실패
- 모바일: 카드형(목록은 날짜·거래처·금액·명세서 버튼이 보이는 카드)
- 연결 기능: F10·F12 / 연결 데이터: orders, order_items, customers
- 후순위·제외: 주문 일괄 편집 2차. **예상 마진 합계 컬럼은 선택 표시(매입단가 있을 때, 참고값)**

### S11 품목별 합산표
- 목적: 도매상 발주용 총 물량 합산(시연 핵심) / 사용자: 회사 소속
- 진입 경로: 대시보드 바로가기 / S9 확정 후
- 주요 UI: 날짜 필터, 거래처 필터, 품목명·단위·총수량·관련 거래처 수, CSV/Excel 내보내기(§8)
- 행동: 필터, 합산 확인, 내보내기
- 결과: 합산표 표시
- 빈 상태: 대상 주문 없음 안내
- 오류 상태: 집계 실패 재시도
- 모바일: 카드형 또는 가로 스크롤(§12)
- 연결 기능: F11 / 연결 데이터: orders, order_items, products
- 후순위·제외: 매입 발주 자동 전송 제외. **예상 매출/예상 마진 컬럼은 선택 표시**(매입단가 있을 때, 참고값 — §5.1 기능정의서)

### S12 거래명세서 미리보기
- 목적: 거래처 납품 명세 인쇄용 미리보기 / 사용자: 회사 소속
- 진입 경로: S10에서 [거래명세서 보기]
- 주요 UI(이카운트 벤치마크 — 더 촘촘한 업무용 문서 레이아웃):
  - **상단 블록**: 공급자 정보(상호/사업자번호 등 회사 정보) · 거래처 정보 · 일자 · 일련번호(채번은 후순위)
  - **라인 표**: 품목명 · 규격(단위) · 수량 · 단가 · 공급가액 — 행 구분선 있는 정돈된 표
  - **하단**: 공급가 합계(= Σ 라인 금액), **금액 한글 표기(선택)**, **VAT 없음 명시**
  - [인쇄] 버튼. 인쇄 시 한 페이지 정돈(가능하면 보존용/거래처용 2부 출력 여지)
- 행동: 미리보기 확인 → 브라우저 인쇄
- 결과: 업무 문서 수준 인쇄용 레이아웃
- 빈 상태: 품목 0줄 경고
- 오류 상태: 단가 미등록 라인 0원 + 경고
- 모바일: 미리보기 위주, 실제 인쇄/공유는 데스크톱 권장(§12)
- 연결 기능: F13 / 연결 데이터: orders, order_items, customers, customer_prices, (회사 정보) companies
- 후순위·제외: **PDF 생성 후순위**, note_number 채번 후순위, **VAT/세금계산서 발행 제외**

### S13 미수금 수동 체크
- 목적: 주문/명세 기준 미수 상태를 수동 체크 / 사용자: 회사 소속
- 진입 경로: 대시보드/거래처 상세(후순위 진입)
- 주요 UI: 거래처별 미수 목록, status 토글(unpaid/partial/paid), 금액·입금액 수동 입력
- 행동: 수동 status 변경
- 결과: 상태 반영
- 빈 상태: 미수 항목 없음
- 오류 상태: 저장 실패
- 모바일: 카드형
- 연결 기능: receivables(수동) / 연결 데이터: receivables
- 후순위·제외: **자동 매칭·오래된 미수금 알림 2차**, 자동 생성 안 함

### S14 설정 / 데이터 관리
- 목적: 내보내기·데이터 관리·원문 삭제 안내 / 사용자: 회사 소속(owner)
- 진입 경로: 메뉴 → 설정
- 주요 UI: JSON/CSV 내보내기, 샘플 데이터 초기화, **발주 원문(raw_text) 삭제 관리 안내**(§14 Q), 회사 정보
- 행동: 내보내기, 샘플 초기화, 원문 삭제
- 결과: 파일 다운로드/초기화 완료
- 빈 상태: 데이터 없음 안내
- 오류 상태: 내보내기 실패
- 모바일: 목록형
- 연결 기능: 내보내기/데이터 관리 / 연결 데이터: 전 테이블(읽기), order_imports(raw_text→null)
- 후순위·제외: 직원 권한/백업 정책 2차

## 5. 대시보드 설계 (S3)

대시보드는 복잡한 ERP 메인이 아니라 **"오늘 할 일" 중심**이다.

반드시 포함:
- **[발주 붙여넣기]** (가장 큰 버튼)
- **[샘플 데이터 시작]**
- 오늘 주문 수
- 오늘 품목별 합산표 바로가기
- 거래처/품목/단가 빠른 등록 바로가기
- 거래명세서 바로가기
- 빈 상태 문구: **"아직 등록된 데이터가 없습니다. 샘플 데이터로 먼저 흐름을 확인해보세요."**

> 제외: 매출 통계/그래프/알림 센터 등 ERP식 위젯. 1차는 "발주→합산표" 동선만 또렷하게.

## 6. 발주 붙여넣기 화면 설계 (S8)

반드시 포함:
- **거래처 선택**(필수, 먼저 선택)
- **원문 붙여넣기 영역**(textarea)
- **예시 문구**: `콩나물 2박스` / `두부 3판` / `미나리 5단`
- **[파싱] 버튼**
- **raw_text 저장 안내**: "붙여넣은 원문은 확인을 위해 저장됩니다."
- **개인정보/민감정보 주의 문구**: "원문에 연락처·메모 등 민감정보가 있을 수 있습니다."
- **원문 삭제 가능 안내**: "원문은 언제든 삭제할 수 있고, 삭제해도 저장된 주문은 유지됩니다."

## 7. 파싱 결과 확인/수정 화면 설계 (S9)

반드시 포함(라인별):
- 원문 라인 / 매칭된 품목 / 수량 / 단위 / **단가(인라인 직접 입력)** / 금액(자동 재계산) / 상태 표시
- **미매칭 품목 경고**(빨강)
- **수량 불확실 경고**(노랑, 예: "세개", "큰거")
- **단가 미등록 경고**(앰버) + **[이 단가 저장]**(입력한 단가를 customer_prices에 저장 → 다음부터 자동 적용)
- **[별칭으로 등록]** 버튼(미매칭 해결 → 재매칭)
- **[주문 확정]** 버튼
- 규칙: **미매칭/수량 불확실 라인이 있으면 확정 불가**(버튼 비활성 + 사유 표시)

> 금액은 `round(단가 × 수량)`이며 단가 수정 시 즉시 재계산. 단가 미등록은 0원 + 경고이되, **그 자리에서 단가를 입력·저장**할 수 있다(이카운트 벤치마크 반영).

## 8. 품목별 합산표 화면 설계 (S11)

반드시 포함:
- **날짜 필터** / **거래처 필터**
- 품목명 / 단위 / **총수량** / 관련 거래처 수
- **CSV/Excel 내보내기**(후보)
- 도매상 발주용으로 **보기 쉬운 형태**(품목 등록순, 큰 글씨 수량)

> 예: "오늘 총 — 콩나물 10박스 / 두부 20판 / 미나리 15단". 이 표가 시연의 핵심.

## 9. 거래명세서 미리보기 화면 설계 (S12)

반드시 포함(이카운트 벤치마크 — 업무 문서 수준 레이아웃):
- **상단**: 공급자(회사) 정보 / 거래처 정보 / 일자 / 일련번호(채번 후순위)
- **라인 표**: 품목 / 규격(단위) / 수량 / 단가 / 공급가액 — 구분선 있는 정돈된 표
- **공급가 합계** (= Σ 라인 금액), **금액 한글 표기(선택)**
- **VAT 계산 없음**(표기·계산 안 함, 명시)
- **[인쇄] 버튼**(브라우저 인쇄, 한 페이지 정돈)
- **PDF 생성은 후순위**

> 현재 HTML 데모보다 더 촘촘하게: 빈 여백 줄이고, 공급자/거래처 블록과 라인 표를 실제 거래명세서처럼 정렬한다.

## 10. 샘플 데이터 화면 설계 (S4)

- **[샘플 데이터 시작]** 버튼
- 포함 데이터 설명: **거래처 · 품목 · 별칭 · 단가 · 발주 예시**

- 샘플 데이터 **초기화/다시 만들기 주의**(기존 데이터와 섞이지 않게)
- 문구: **"먼저 흐름만 확인해보세요."**

## 11. 빠른 세팅 UX

초기 세팅 대행을 고려한 입력 편의:
- 거래처 빠른 등록(연속 입력)
- 품목 빠른 등록(연속 입력)
- 별칭 빠른 등록(칩 입력)
- 단가 빠른 입력(거래처×품목 표에서 바로 입력)

- 전제: **사용자가 직접 모든 데이터를 넣게 하지 않는다**(우리가 대행 가능한 화면 구성)

## 12. 모바일 화면 고려

- 사장님이 **휴대폰으로 볼 가능성** 높음 → 주요 화면 반응형.
- **발주 붙여넣기 textarea** 사용성(큰 입력창, 붙여넣기 쉬움).
- **표가 너무 넓어지는 문제**: 합산표·단가표는 모바일에서 **카드형 또는 가로 스크롤**.
- **거래명세서 인쇄/공유**는 데스크톱이 더 적합할 수 있음(모바일은 미리보기 위주).

| 우선순위 | 화면 |
|---|---|

## 14. 화면 설계 확정값 (Codex 리뷰 반영)

§14의 남은 질문 5개를 아래로 확정한다.

| Q | 질문 | 확정 | 이유 |
|---|---|---|---|
| Q1 | 샘플 데이터 적재 시점 | **회사 생성 후 적재** | 데이터는 `company_id` 기준 저장 → RLS/회사 격리 구조와 일치 |
| Q2 | 단가 미등록 품목 | **0원 + 경고 유지** | 발주 흐름을 막지 않고 단가 등록 필요를 알림(1차 적합) |
| Q3 | 모바일 거래명세서 인쇄 | **모바일은 미리보기 중심, 실제 인쇄는 데스크톱 권장** | 인쇄/출력은 PC/프린터 환경이 자연스러움 |
| Q4 | 발주 원문 삭제 버튼 위치 | **S14 설정/데이터 관리에 기본 배치**. S8에는 저장 안내 + 삭제 가능 안내만 표시 | 입력 중 실수 삭제 방지, 원문 삭제는 관리성 작업으로 분리 |
| Q5 | 샘플/실제 데이터 분리 | **1차는 같은 회사에 넣되 샘플 표시 + 초기화 가능** | 샘플 회사 분리는 구조가 복잡 → 후순위 |

> 위 확정은 S4(샘플 적재)·S8(붙여넣기 안내)·S12(명세서 인쇄)·S14(원문 삭제/데이터 관리) 화면 정의에 반영된다. 상세 샘플 데이터는 `docs/sample-data-definition.md` 참조.
