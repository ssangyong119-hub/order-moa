# 오더모아 웹 MVP 전략

작성일: 2026-06-06

## 1. 전략 결론

오더모아는 로컬 정적 앱에서 끝내지 않고 웹 서비스 MVP로 전환한다.

웹 MVP의 목적은 완성형 ERP를 만드는 것이 아니라, 설문에서 가장 강하게 확인된 문제를 실제 사용자에게 검증하는 것이다.

핵심 검증 문장:

> 카톡/문자 발주를 붙여넣으면 거래처별 주문표와 품목별 총 발주표가 만들어지고, 단가/미수금/거래명세서까지 이어지는 흐름이 실제 납품업자에게 돈 낼 가치가 있는가?

## 2. 설문에서 확인된 근거

응답 수는 5건으로 작지만 방향성은 선명하다.

강한 신호:

- 카카오톡 개인 채팅 주문: 4건
- 문자 주문: 4건
- 카카오톡 단체방 주문: 3건
- 카톡 주문을 ERP/엑셀/장부에 매일 옮겨 적음: 3건
- 가장 도움이 될 기능 1위: 카카오톡 주문 내용을 주문서로 자동 정리
- 자유응답 반복 표현: "카톡 및 문자 발주 자동 취합"

보조 신호:

- 거래처별 단가 변경이 자주 있음: 3건
- 믿을 수 없는 단가/불투명한 단가 언급
- 품목별 마진 계산기 요구
- 미수금/입금 확인, 오래된 미수금 알림 요구
- 월말 세무기장 자료 정리 요구

## 3. 웹으로 전환해야 하는 이유

로컬 앱의 장점:

- 빠르게 만들 수 있다.
- 로그인/서버/배포 없이 화면 흐름을 검증할 수 있다.
- 개인 실험에는 충분하다.

로컬 앱의 한계:

- 여러 PC에서 같은 데이터를 쓰기 어렵다.
- 직원과 공유할 수 없다.
- 거래처/직원별 권한 분리가 어렵다.
- 실제 사업 데이터 백업과 보안이 약하다.
- 장기적으로 유료 서비스 전환이 어렵다.

웹 MVP가 필요한 이유:

- 사장, 직원, 사무실 PC, 현장 모바일이 같은 데이터를 봐야 한다.
- 발주/단가/미수금/거래명세서는 사업자별 데이터 격리가 필요하다.
- 추후 거래처 주문 링크, 파일 첨부, OCR, 알림 기능으로 확장해야 한다.
- 실제 유료 검증에는 로그인, 회사 단위 데이터, 백업이 필요하다.

## 4. 웹 MVP 1차 범위

반드시 포함:

1. 로그인
2. 회사/사업장 생성
3. 거래처 등록
4. 품목 등록
5. 거래처별 판매 단가 등록
6. 카톡/문자 발주 붙여넣기
7. 사람이 확인/수정하는 발주 파싱 화면
8. 거래처별 주문표
9. 품목별 총 발주/출고 합산표
10. 거래명세서 미리보기
11. JSON 또는 엑셀 내보내기

가능하면 포함:

1. 단가 변경 이력
2. 품목 별칭 관리
3. 미수금 수동 체크
4. 모바일 보기 최적화

1차에서 제외:

1. 카카오톡 자동 읽기
2. 문자 자동 수집
3. 홈택스 세금계산서 직접 발행
4. 은행 계좌 자동 입금 매칭
5. 완전 자동 OCR
6. 이카운트 직접 연동

## 5. MVP 검증 기준

웹 MVP는 기능 완성도가 아니라 실제 검증을 위해 만든다.

검증 지표:

- 사용자가 실제 카톡/문자 발주를 10건 이상 입력해보는가?
- 발주 취합 시간이 기존보다 줄어드는가?
- 품목별 총 발주표가 실제 도매상 발주에 쓰이는가?
- 거래처별 주문표/거래명세서가 실제 업무에 충분한가?
- 거래처별 단가 관리가 이카운트보다 쉽다고 느끼는가?
- 월 3만~5만 원 지불 의사가 생기는가?
- 기존 ERP를 완전히 대체하지 못해도 보조 도구로 쓸 의사가 있는가?

성공 기준:

- 최소 2명 이상이 실제 발주 데이터를 넣어보고 다시 써보겠다고 말한다.
- 최소 1명 이상이 월 사용료 지불 의사를 구체적으로 말한다.
- 발주 취합/합산표 기능이 가장 유용하다는 피드백이 나온다.

실패 기준:

- 사용자가 카톡 내용을 붙여넣는 것조차 번거롭다고 느낀다.
- 거래처/품목/단가 초기 등록이 너무 오래 걸려 사용을 포기한다.
- 거래명세서/미수금/세금 기능 없이는 의미가 없다고 판단한다.
- 기존 ERP와 병행할 가치가 없다고 말한다.

## 6. 할 수 있는 것과 할 수 없는 것

지금 바로 구현 가능:

- 웹 로그인
- 회사별 데이터 분리
- 거래처/품목/단가 CRUD
- 발주 붙여넣기
- 규칙 기반 1차 파싱
- 사람이 확인/수정하는 발주 편집
- 품목별 합산표
- 거래처별 주문표
- 거래명세서 미리보기
- 엑셀/CSV 내보내기

조건부 가능:

- 사진 발주 OCR
- 카카오톡 공유 텍스트 자동 포맷
- 거래처용 주문 링크
- 모바일 웹 앱 형태의 홈 화면 추가
- Supabase Storage 파일 첨부

당장 어려움:

- 카카오톡 메시지 자동 읽기
- 네이버/문자 앱 자동 수집
- 홈택스 세금계산서 직접 발행
- 은행 계좌 자동 입금 매칭
- 이카운트 양방향 연동

보류 이유:

- 외부 서비스 정책/권한/법적 리스크가 있다.
- 정확도가 낮으면 사용자가 더 불안해할 수 있다.
- MVP 검증에는 완전 자동화가 필요하지 않다.

## 7. 권장 제품 순서

1단계:

- 발주 붙여넣기와 수동 확인
- 거래처/품목/단가
- 합산표와 거래명세서

2단계:

- 품목 별칭
- 단가 변경 이력
- 매입가/판매가/마진
- 미수금 수동 관리

3단계:

- 거래처 주문 링크
- 파일 첨부
- OCR 보조
- 직원 권한

4단계:

- 세금계산서 발행 자료 정리
- 세무사 전달용 월말 리포트
- 알림/리마인더

## 8. 공식 자료 근거

- Vercel Docs: Next.js 배포와 환경 변수 관리에 적합하다.
