## 1차 — 좁은 MVP 완성 (현재)

### 목표
"카톡 발주 붙여넣기 → 확인 → 확정 → 합산표 → 매입처 발주 문장 → 거래명세서"가 **샘플이 아닌 내 데이터로**, **새로고침해도 남게** 돌아간다.

### 완료된 것 (2026-07-07 기준)
- 단위 1~7: 스캐폴드, 스키마/RLS 설계·적용, 화면 설계, 프로토타입, 데모 핵심 흐름, 합산표+복사 문장
- 8a: 인증/회사/RLS 실측까지 (A/B 격리 0/0/0, 위조 insert 42501 차단)
- 8b 코드: 주문 DB 저장/조회, 시드 멱등(ensureSeed/diffSeedRows)
- 파서 개선: 단위 사전 확장, 규격 숫자 구분(1kg 2봉), 다중 후보 확인(숙주), 실제 발주 fixture
- UI: 좌측 사이드바 셸, 품목 검색, 매입처별 발주 문장(체크 기본 비움), 명세서 빈행/인쇄 보정, 미매칭 품목 즉석 신규 등록, 개발용 데모 진입

### 남은 것 (완료 조건)

| # | 작업 | 완료 조건 | 크기 |
|---|---|---|---|
| 1 | 기준정보 관리 1차 | 거래처/품목·별칭/단가를 사용자가 직접 추가·수정·보관(archive)할 수 있다. 사이드바 "준비 중" 3개가 실화면이 된다 | 큼 |
| 2 | 매입처 DB화(1차 보강) | `ordermoa_suppliers` + `products.purchase_supplier_id`로 기본 매입처가 새로고침 후에도 유지된다 | 중간 |
| 3 | 8b 실사용 실측 | 실로그인→발주 확정→F5 후 주문 목록 유지, Table Editor에서 row 확인 → 진행현황 8b "완료" | 짧음 |
| 4 | 8c | 저장된 주문에서 합산표/명세서 재출력, 거래처별 월 합계, raw_text 저장 | 중간 |
| 5 | 실제 발주 테스트 라운드 | 가명화된 실발주 장문을 반복 투입해 파서/검색/매입처 분리 검증 | 반복 |

### 선행 조건
- 기준정보 CRUD는 현행 스키마로 가능하다.
- 매입처 DB화는 additive 마이그레이션이 필요하므로 Codex 승인 후 별도 단위로 진행한다.

### 위험 요소
- 이메일 매직링크 rate limit → 실측 지연 (완화: 실측만 실브라우저로 분리, 나머지 작업 병행)
- 기준정보 화면이 page.tsx를 더 비대화 → **뷰 분리와 함께 진행**
- "이왕 만드는 김에" 확장 압력 → 차수 딱지 먼저

## 1.5차 — MVP 다듬기

### 목표
1차를 실사용하며 걸리는 턱을 제거한다. **새 업무 영역은 열지 않는다.**

### 포함

| 작업 | 내용 | 왜 지금 |
|---|---|---|
| 매입처 관리 다듬기 | 1차 보강에서 만든 매입처 DB/화면의 검색·정렬·보관 처리 개선 | 2차 원가/발주이력 전 사용성 보강 |
| 거래명세서 양식 개선 | 공급자/거래처 블록, 규격 컬럼, 금액 한글 표기(선택) — `delivery-note-print-spec.md` 기준 | 실서류로 쓰려면 필요. 인쇄는 여전히 브라우저 |
| 엑셀 업로드/다운로드 | 거래처/품목/단가 일괄 입력, 합산표·주문 내보내기 | 초기 세팅 대행·이카운트 병행 사용자 배려 |
| 샘플 초기화/재설치 | 설정 화면에서 샘플 삭제·재시드 | 데모→실데이터 전환 시 필요 |
| 모바일 최적화 | 아침 흐름(붙여넣기→확정) 390px 재점검 | 실사용 피드백 반영 |
| 백업/내보내기 | 회사 데이터 JSON/엑셀 덤프 | 공유 Supabase 프로젝트 리스크 완화 겸용 |

### 제외 (이 단계에서 하지 않음)
미수금, 세금계산서 정리, PDF 파일 생성, 단가 이력, 직원 권한.

### 선행 조건
- 1차 완료(특히 기준정보 CRUD, 매입처 DB화, 8c)

### 위험 요소
- 마이그레이션이 공유 프로젝트에 추가됨 → `ordermoa_` 접두사·RLS·트리거 체크리스트 엄수
- 엑셀 업로드는 검증 없는 대량 쓰기 경로 → 미리보기+확인 단계 필수, 실패 행 리포트

## 2차 — ERP 확장 (돈의 흐름)

### 목표
주문(매출)만 있던 시스템에 **미수금·원가·세금계산서 근거**를 추가한다. 여전히 "정확 회계"가 아니라 "사장님 장부" 수준.

### 포함

| 작업 | 내용 | 근거 데이터 |
|---|---|---|
| 미수금/입금 | 수동 미수 체크(unpaid/partial/paid) + 입금 기록. `receivables` 테이블 생성 | 스키마 여지 이미 설계됨(db-schema §4.11) |
| 거래처별 월 정산표 | 월 매출 합계 + 미수 잔액 | 1차 orders/order_items 그대로 |
| 세금계산서 근거 정리 | 월·거래처 매출합계 vs 발행액 대조 표(`tax_invoice_summaries`) — **발행은 안 함** | 1차부터 보존한 기간 금액 |
| 매입처별 원가/발주 이력 | 매입처별 매입 단가 기록, 발주 문장 보낸 기록 저장 | 1차 보강 suppliers |
| 단가 변경 이력 | `price_history` — 단가 수정 감사 추적 | customer_prices |
| 정확도 있는 마진 | 매입처 원가 기반 마진(여전히 재고 평가 없는 근사) | 원가 이력 |
| 직원 권한 UI | staff 로그인·역할 제한 | company_members.role |
| 저장형 명세서 + PDF | delivery_notes 저장·채번, 서버 PDF 생성 | 1차 명세서 |
| 주문 수정/반품 | 확정 주문의 라인 수정·부분 취소 이력 | orders soft 규칙 확장 |

### 선행 조건
- 1.5차 완료 + **실사용자 최소 1명이 1차 흐름을 4주 이상 사용** (사용 없이 2차를 만들면 전부 추측)
- 미수금·정산의 화면 요구를 실사용 피드백으로 재확인

### 위험 요소
- 가장 큰 단계 — 쓰기 경로가 많아짐. 모듈별로 잘게 단위 분할 필수
- "정확 회계"로 오해받기 시작하는 지점 → 참고값 문구·경계 문서화 유지
- 주문 수정은 스냅샷 원칙과 긴장 관계 → 수정 이력을 남기는 설계 선행

## 3차 — 고도화/자동화

### 목표
쌓인 데이터로 시간을 더 아껴준다. 새 데이터 입력보다 **조회·제안** 중심.

### 포함 (전부 2차 데이터 위의 조회/제안)

- 리포트: 품목별 판매 추이, 매입처별 발주 추이, 거래처 매출 순위, 대시보드 고도화
- 좁은 재고: 입출고 수량 기록·창고 이동·반품 반영 (**재고 평가·실사·로트는 하지 않음**)
- 마감: 월 마감 잠금(마감 후 과거 주문 수정 차단)
- 오래된 미수금 알림, 발주 패턴 기반 품목 제안(사람 확정 유지)
- 감사 로그, 데이터 보관 정책(raw_text 자동 정리 등)
- 오더모아 전용 Supabase 프로젝트 이전 검토(공유 프로젝트 탈출)

### 선행 조건
- 2차 안정화 + 복수 회사 사용(멀티테넌트 실증)

### 위험 요소
- 재고는 범위가 폭발하는 영역 — "수량만, 평가 없음" 경계를 문서로 먼저 박기
- 프로젝트 이전은 데이터 마이그레이션 리스크 — 백업/내보내기(1.5차)가 보험

## 장기 (검증 후 결정)

| 항목 | 조건 |
|---|---|
| 거래처 주문 링크(거래처가 직접 입력) | 실사용자들이 원하는지 검증 후 실험 |
| 홈택스 연계 검토 | 세금계산서 근거 정리(2차)가 실제로 쓰인 뒤 |
| 멀티 사업장/지점 | 복수 회사 운영 수요 확인 후 |

## 제외 (착수 금지 — 재논의는 사용자 명시 요청 시만)

| 항목 | 이유 |
|---|---|
| OCR/사진 발주 인식 | 정확도·운영 리스크 대비 가치 미검증 |
| 카카오톡 자동 읽기 | 정책/권한 리스크 |
| 이카운트 연동 | 전체 대체가 아닌 앞단 도구라는 정체성 유지 |
| 세금계산서 직접 발행 | 법적 책임 영역, 근거 정리까지만 |
| 은행 자동 매칭 | 오픈뱅킹 연동 비용 대비 미검증 |
| 전체 재고 ERP(평가·실사·로트) | 범위 폭발 |

## 단계 이동 판정 기준 (요약)

- 1차 → 1.5차: §1차 완료 조건 5개 전부 + 검증 한 세트 green
- 1.5차 → 2차: 1차/1.5차 안정화 + **실사용 4주**
- 2차 → 3차: 미수금·정산 실사용 + 복수 회사
- 어느 단계든: 새 요구는 "확정 데이터 위의 조회인가 / 새 쓰기 경로인가 / 외부 연동인가"로 차수 판정(헌장 §4)
