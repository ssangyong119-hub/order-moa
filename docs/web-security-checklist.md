# 오더모아 웹 보안/개인정보 체크리스트

작성일: 2026-06-06

## 1. 보안 원칙

오더모아는 단순 주문 앱이 아니라 사업자 데이터를 다룬다.

민감한 데이터:

- 거래처명
- 담당자명
- 전화번호
- 사업자번호
- 주소
- 거래명세서
- 품목별 단가
- 매입가/판매가/마진
- 미수금
- 입금 내역
- 세금계산서 관련 금액
- 카카오톡/문자 발주 원문
- 발주 사진

기본 원칙:

- 회사별 데이터 격리를 최우선으로 한다.
- 사용자는 자기 회사 데이터만 볼 수 있어야 한다.
- 첨부파일은 최소한으로 저장한다.
- 세무/계산서 기능은 직접 발행보다 자료 정리부터 시작한다.
- MVP에서도 보안 구조를 나중으로 미루지 않는다.

## 2. 인증

필수:

- 이메일 로그인 또는 카카오/네이버 로그인 중 하나
- 세션 만료 처리
- 로그아웃
- 비밀번호 직접 저장 금지
- 인증 제공자 사용

권장:

- Supabase Auth 사용
- 최초 가입 시 회사/사업장 생성
- 초대 기반 직원 추가는 2단계로 보류

보류:

- 자체 비밀번호 인증 구현
- 사업자 공동인증서 로그인
- 네이버/카카오 비즈니스 계정 연동

## 3. 권한 모델

초기 권한:

- owner: 회사 생성자, 모든 데이터 접근
- staff: 발주/거래처/품목 입력 가능

MVP 1차에서는 owner만 구현해도 된다.

2단계 권한:

- owner: 설정/단가/정산 포함 전체 접근
- manager: 발주/거래명세서/미수금 접근
- staff: 발주 확인/출고표만 접근

권한 원칙:

- 회사 ID를 모든 주요 테이블에 포함한다.
- 쿼리는 항상 회사 ID 기준으로 제한한다.
- 클라이언트에서 숨기는 것만으로 권한을 처리하지 않는다.

## 4. 데이터 격리

Supabase 사용 시 필수:

- 모든 업무 테이블에 `company_id` 포함
- Row Level Security 활성화
- `auth.uid()` 기준으로 사용자의 회사 접근 권한 확인
- Storage 파일도 회사별 경로 또는 정책으로 분리

테이블 예:

- companies
- company_members
- customers
- products
- customer_prices
- orders
- order_items
- delivery_notes
- receivables
- uploaded_files

## 5. 입력 검증

필수 검증:

- 거래처명 빈 값 방지
- 품목명 빈 값 방지
- 수량은 0보다 커야 함
- 단가는 0 이상이어야 함
- 날짜 형식 검증
- 회사 소유 데이터인지 확인

파싱 입력:

- 카톡/문자 원문은 길이 제한
- 붙여넣기 원문 저장 여부를 명확히 결정
- 저장한다면 원문 보관 기간 설정

## 6. 첨부파일/OCR 보안

MVP 1차:

- 파일 업로드/OCR은 제외한다.

2단계에서 파일을 받는 경우:

- 허용 파일 형식 제한: jpg, jpeg, png, pdf
- 파일 크기 제한
- 회사별 파일 경로 분리
- 원본 파일 삭제 기능
- 민감정보 포함 가능성 안내
- OCR 결과는 사람이 확인 후 저장

주의:

- 카톡 캡처와 거래명세서에는 개인정보와 거래금액이 포함될 수 있다.
- OCR 정확도가 낮으면 금전 사고로 이어질 수 있다.

## 7. 세금계산서/세무 기능

MVP 1차:

- 세금계산서 직접 발행 제외
- 월별 거래처별 매출 합계와 발행 필요 금액 표시까지만 고려

2단계:

- 세금계산서 발행 여부 수동 체크
- 과세/면세 구분
- 부족/초과 발행 금액 표시
- 세무사 전달용 엑셀 출력

보류:

- 홈택스 직접 발행
- 전자세금계산서 API 연동
- 세무 대행성 판단이 필요한 기능

## 8. 로그와 감사 추적

초기에는 최소 로그:

- 주문 생성/수정 시간
- 단가 변경 시간
- 단가 변경 전/후 금액
- 거래명세서 생성 시간

중요:

- 단가 변경 이력은 제품 가치이면서 감사 로그 역할도 한다.
- 누가 바꿨는지 기록하려면 직원 계정이 필요하다.

## 9. 백업과 복구

MVP:

- DB 정기 백업은 Supabase 프로젝트 설정에 의존
- 사용자 데이터 JSON/엑셀 내보내기 제공

권장:

- 주요 테이블 CSV 내보내기
- 삭제 전 확인
- 삭제 대신 비활성화/soft delete 검토

## 10. 보안 체크리스트

웹 MVP 구현 전:

- [ ] 모든 주요 테이블에 `company_id`가 있는가?
- [ ] 사용자가 자기 회사 데이터만 접근하는가?
- [ ] RLS 정책이 켜져 있는가?
- [ ] 공개 API에서 회사 ID를 임의로 바꿔도 차단되는가?
- [ ] 단가/미수금/거래명세서가 다른 사용자에게 노출되지 않는가?
- [ ] 환경 변수가 Git에 올라가지 않는가?
- [ ] 첨부파일 저장을 아직 하지 않는다면 UI에 업로드 기능이 없는가?
- [ ] 개인정보 처리 안내 문구가 있는가?
- [ ] 원본 발주 텍스트 저장 여부가 명확한가?

웹 MVP 배포 전:

- [ ] 테스트 계정과 실제 계정을 분리했는가?
- [ ] 프로덕션 DB와 개발 DB를 분리했는가?
- [ ] Vercel 환경 변수에 Supabase 키를 설정했는가?
- [ ] 서비스 role key를 클라이언트에 노출하지 않는가?
- [ ] 로그에 개인정보가 남지 않는가?

## 11. 당장 결정

현재 결정:

- 웹 MVP는 로그인/회사별 데이터 격리를 포함한다.
- MVP 1차는 파일 업로드/OCR/카카오톡 자동 연동을 제외한다.
- 발주 원문은 기본 저장하지 않고, 파싱 후 사용자가 확정한 주문 데이터만 저장하는 방향을 우선 검토한다.
- 단가 변경 이력은 빠르게 포함한다.
