# 도소매 납품 ERP 아이디어 추적 문서

작성일: 2026-05-25

최근 업데이트: 2026-05-26

## 1. 현재 목표

지방 소상공인, 특히 도소매 납품업자를 대상으로 실제 업무 불편을 조사하고, 돈을 내고 쓸 가능성이 있는 작은 ERP 또는 업무 자동화 서비스를 발굴한다.

초기 방향은 완성형 ERP를 바로 만드는 것이 아니라, 도소매 납품업자의 반복 업무 중 가장 고통이 크고 도입 가치가 높은 문제를 찾는 것이다.

## 2. 현재 핵심 가설

도소매 납품업자는 거래처 주문, 거래명세서, 단가, 출고, 미수금, 세금계산서, 월말 정산 업무를 여러 도구로 나누어 처리하고 있을 가능성이 높다.

특히 다음 문제가 반복될 수 있다.

- 카카오톡, 전화, 문자 등으로 흩어진 주문을 다시 정리해야 한다.
- 거래처마다 상품 단가가 달라 단가 실수가 발생할 수 있다.
- 주문 마감 후 오늘 실어야 할 물량을 상품별로 합산해야 한다.
- 거래명세서 작성과 수정이 반복 업무가 된다.
- 미수금과 오래된 미수금을 한눈에 확인하기 어렵다.
- 월말 세금계산서 발행 금액과 실제 거래 금액의 부족/초과를 관리해야 한다.
- 세무기장용 자료를 매월 따로 정리해야 한다.

## 3. 지금까지 나온 MVP 후보

가장 현실적인 첫 MVP 후보:

> 카톡/전화 주문을 거래처별로 정리하고, 거래처별 단가를 적용해서, 거래명세서와 출고 리스트를 바로 만드는 도구

이 방향이 좋은 이유:

- 매일 발생하는 업무를 줄인다.
- 기존 ERP 전체를 대체하지 않아도 된다.
- 거래처의 행동 변화를 강하게 요구하지 않는 방향으로 시작할 수 있다.
- 이후 미수금, 세금계산서, 세무기장 자료 정리로 확장할 수 있다.

## 4. 우선 검증할 기능 5가지

1. 주문 통합 정리
   - 카카오톡, 전화, 문자 등으로 들어온 주문을 한 화면에서 거래처별로 정리한다.

2. 거래처별 단가 자동 적용
   - 같은 상품이라도 거래처별 단가가 다를 때 자동으로 적용하고, 단가 변경 이력을 관리한다.

3. 출고/배송 준비 리스트 자동 생성
   - 거래처별 명세서뿐 아니라 상품별 총 출고 물량을 합산한다.

4. 미수금/입금 확인 대시보드
   - 거래처별 미수금, 오래된 미수금, 입금 확인 필요 항목을 한눈에 보여준다.

5. 월말 정산/세무자료 자동 정리
   - 세금계산서 발행 금액 부족/초과, 거래처별 월 매출 합계, 세무기장 자료를 정리한다.

## 5. 설문 진행 방식

현재 설문은 네이버폼으로 배포한다.

검토용 HTML 초안:

- `survey-draft.html`

네이버폼 운영 방향:

- 1차 대상은 지인 소개 기반 약 10명
- 로그인 필수 ON으로 설정
- 이미지/파일 업로드 가능하게 설정
- 단, 캡처 첨부는 선택사항으로 안내
- 민감정보는 반드시 가리고 업로드하도록 안내
- 응답 기간은 2~3일 정도로 짧게 운영
- 결과는 비공개
- 연락처를 받는 경우 개인정보 수집/제공 동의 문구 포함

## 6. 설문 대상 우선순위

1순위:

- 식당, 카페, 마트 등에 납품하는 도소매업자

2순위:

- 식자재, 농산물, 축산, 수산 도매 사장님
- 경매 도매를 보는 사장님

3순위:

- 공산품, 생활용품 납품업자

4순위:

- 주류, 음료 납품업자

5순위:

- 소규모 제조 후 납품하는 사업자
- 예: 반찬, 떡, 식품가공, 베이커리 납품

초기 설문에 가장 적합한 조건:

- 거래처 10곳 이상
- 반복 납품이 있음
- 거래명세서, 세금계산서, 미수금 관리가 있음
- 주문을 카카오톡, 전화, 문자, ERP 등으로 받음

## 7. 네이버폼 작성 시 주의사항

질문 번호는 네이버폼이 자동 생성하는 번호와 별개로 질문 제목에 직접 적는다.

예:

- `1-1. 현재 업종 또는 취급 품목은 무엇인가요?`
- `1-2. 주로 납품하는 거래처는 어떤 곳인가요?`

질문 유형 기준:

- 직접 입력: 주관식 단답형 또는 주관식 서술형
- 하나만 선택: 객관식, 복수 선택 OFF
- 여러 개 선택: 객관식, 복수 선택 ON
- 사진/파일 첨부: 이미지/파일, 로그인 필수 ON 필요

카테고리형은 이번 설문에서 거의 사용하지 않는다.

## 8. 개인정보 및 민감정보 안내 문구

설문 안내문 또는 파일 업로드 질문에 아래 내용을 포함한다.

> ERP 화면, 카카오톡 발주, 거래명세서 캡처를 첨부해주시면 큰 도움이 됩니다. 단, 거래처명, 전화번호, 사업자번호, 계좌번호 등 민감정보는 반드시 가리고 올려주세요. 캡처 첨부는 선택사항이며, 부담되시면 첨부하지 않으셔도 됩니다.

연락처를 받을 경우 개인정보 동의 문구:

> 수집 항목: 이름 또는 별칭, 연락처, 설문 응답 내용, 선택적으로 첨부한 이미지/파일
>
> 수집 목적: 도소매 납품 업무 개선 서비스 기획 및 추가 인터뷰 연락
>
> 보관 기간: 설문 종료 후 3개월 이내 삭제
>
> 동의하지 않을 경우 연락처 제공 및 추가 인터뷰 참여가 제한될 수 있습니다.

## 11. 2026-05-26 이카운트 조사 메모

친구가 월 4만 원 정도로 사용 중이라고 한 ERP는 이카운트로 확인됨.

공개 가격 정책 기준:

- ERP 기본 사용료 월 4만 원
- 사용자 수 무제한
- 용량 무제한
- 회계, 자금, 세무, 인사, 급여, 영업, 판매, 구매, 재고, 물류, 생산, 제조, 원가 등 전 기능 제공
- 전자세금계산서, 모바일 앱, 온라인 수발주 시스템 등 부가 기능 제공

관찰한 화면 기준:

- 친구는 전체 기능 중 일부만 사용하는 것으로 보임.
- 현재 주로 보는 영역은 판매조회, 거래명세서, 불러온 전표, 출력물, 재고/영업관리 쪽으로 추정됨.
- 판매조회 화면에서 거래처명, 품목명 요약, 금액 합계, 거래유형, 창고명, 인쇄, 불러온 전표 조회가 가능함.
- 불러온 전표 화면에서 품목코드, 품목명, 규격, 수량이 품목별로 정리됨.
- 거래명세서 출력 화면은 실제 납품 현장에서 바로 사용할 수 있을 정도로 완성도가 높음.

전략적 판단:

- 이카운트는 가격과 기능 폭이 강해 정면 승부 대상이 아님.
- 월 4만 원에 완성형 ERP를 제공하기 때문에 단순한 ERP 복제는 경쟁력이 낮음.
- 기회는 이카운트가 너무 넓고 복잡해서 사용자가 실제로 10분의 1만 쓰는 지점에 있음.
- 초기 제품은 이카운트를 대체하는 ERP가 아니라, 특정 업종의 현장 흐름을 더 쉽게 만드는 보조 도구 또는 업종 특화 인터페이스가 되어야 함.

가능한 차별화 방향:

1. 도소매 식당 납품업 전용 화면
   - 이카운트의 범용 메뉴 대신 납품 사장님이 매일 쓰는 주문, 출고, 명세서, 미수금만 한 화면에 묶는다.

2. 카카오톡/전화 주문 정리 보조
   - 거래처가 기존 방식으로 주문해도, 사장님이 주문을 빠르게 정리할 수 있게 돕는다.

3. 출고 준비 중심 UX
   - 거래명세서보다 먼저 "오늘 차에 실을 전체 물량"과 "거래처별 납품 목록"을 쉽게 만든다.

4. 이카운트 사용자의 불편 보완
   - 이미 이카운트를 쓰는 사람에게도 필요한 간단한 보조 툴을 검토한다.
   - 예: 주문 복사 정리, 품목명 매칭, 출고 합산표, 카톡 전달용 요약.

5. 업종 특화 템플릿/세팅 대행
   - 제품 자체보다 "식당 납품업용 이카운트 세팅/운영 템플릿"이 사업 기회가 될 수도 있음.

다음 설문 분석에서 특히 확인할 것:

- 이미 이카운트 같은 ERP를 쓰는 사람도 불편한 점이 있는지
- ERP를 쓰지만 기능이 너무 많거나 어렵다고 느끼는지
- 실제로 매일 쓰는 기능은 무엇인지
- ERP 외부에서 따로 처리하는 업무가 무엇인지
- 카카오톡 주문, 출고 합산, 단가 변경, 미수금 확인 중 어디가 가장 큰 고통인지

## 12. 2026-05-26 친구 통화 메모

통화에서 확인된 핵심:

- 친구는 이카운트를 월 4만 4천 원 정도에 사용 중.
- 이카운트에는 많은 기능이 있지만 실제로 쓰는 기능은 10분의 1 정도.
- 주로 편하게 느끼는 부분은 거래명세서 출력, 기존 거래처/품목/단가 데이터 저장, 이전 입력 데이터 불러오기.
- 현재 사용 방식은 "발주가 자동으로 ERP에 들어가는 구조"가 아님.
- 거래처에서 카카오톡 등으로 발주가 오면 친구가 다시 프로그램에 직접 입력해야 함.
- 프로그램에 입력한 뒤 거래명세서가 생성되고, 모바일/카톡에서 명세서 확인 또는 전달이 가능한 구조로 보임.
- 품목과 단가는 미리 등록해두고 사용함.
- 단가나 품목이 변동되면 그때그때 수동 수정해야 함.
- 거래처 중에는 발주 내용을 텍스트로 보내는 사람도 있고, 손글씨/종이/메모를 사진으로 찍어 보내는 사람도 있음.
- 사진으로 온 발주는 그대로 자동 입력하기 어려워 사람이 보고 받아 적는 상황.
- 여러 거래처에서 같은 품목을 주문하면 전체 물량 합산도 사람이 직접 해야 함.
- 프로그램을 쓰는 이유는 수기 장부, 영수증 분실, 기록 누락 위험을 줄이고 프린트/저장을 편하게 하기 위해서.
- 주변에는 이카운트 외에도 복덩이, 중도매인용 프로그램 등 다른 프로그램을 쓰는 사람도 있음.

앱 핵심 방향 업데이트:

> 기존 ERP를 완전히 대체하기보다, 카카오톡/사진/전화로 들어온 발주를 정리해서 거래명세서 입력과 출고 물량 합산을 쉽게 만드는 도소매 납품업 전용 보조 도구.

가장 강한 문제:

1. 카톡 발주를 ERP에 다시 입력해야 한다.
2. 사진으로 온 발주를 사람이 보고 받아 적어야 한다.
3. 거래처별 발주를 모아 상품별 총 물량을 합산해야 한다.
4. 거래처별 단가와 품목 정보는 이미 ERP에 있지만, 발주 입력 전 단계가 수작업이다.
5. 기존 ERP는 거래명세서 출력과 저장에는 좋지만, 발주 수집/정리에는 약하다.

현재 MVP 후보:

1. 카톡 발주 붙여넣기 정리
   - 거래처명, 품목명, 수량, 단위, 비고를 표로 변환한다.

2. 사진 발주 OCR 보조
   - 손글씨/메모/주문표 사진에서 품목과 수량을 뽑고, 사람이 확인/수정한다.

3. 품목 별칭 매칭
   - 예: "콩나물", "콩", "콩나물박스" 등을 등록 품목 후보로 매칭한다.

4. 출고 합산표
   - 여러 거래처 주문을 합산해 "오늘 총 숙주 20박스, 콩나물 10박스, 두부 20판"처럼 보여준다.

5. 거래명세서/ERP 입력용 표
   - 기존 ERP에 입력하기 쉬운 형태로 거래처별 주문표를 정리한다.

주의할 점:

- 카카오톡 메시지를 자동으로 직접 읽는 기능은 정책/권한/환경 이슈가 있으므로 첫 버전에서 무리하지 않는다.
- 첫 버전은 "카톡 내용 복사해서 붙여넣기"와 "사진 업로드 후 OCR" 정도가 현실적.
- 완전 자동화보다 "사람이 마지막으로 확인하고 수정하는 반자동"이 더 안전하다.
- 이카운트와 경쟁하기보다 이카운트 사용 전 단계의 수작업을 줄이는 보조 도구로 시작하는 것이 좋다.

## 16. 2026-06-06 웹 MVP 전환 기획

로컬 정적 MVP는 실험용으로 유지하되, 실제 서비스 방향은 웹 MVP로 전환한다.

현재 권장 기술 스택:

- Next.js
- Supabase Auth
- Supabase Postgres
- Supabase Row Level Security
- Vercel
- TypeScript

- 로그인
- 회사/사업장 생성
- 거래처/품목/단가
- 카톡/문자 발주 붙여넣기
- 사람이 확인/수정하는 반자동 파싱

- 거래명세서 미리보기
- JSON/CSV/Excel 내보내기
