# Claude 공유용 오더모아 프로젝트 히스토리

작성일: 2026-06-06

## 1. 출발점

사용자는 지방 소상공인과 도소매 납품업자를 대상으로 ERP 또는 업무 자동화 서비스를 만들고 싶어 했다.

처음 관찰한 현장:

- 지인이 도소매/식당 납품 업무를 하고 있음
- 카카오톡으로 여러 거래처에서 발주를 받음
- 기존 ERP를 월 4만 원대에 사용 중
- 거래명세서 출력과 판매조회는 ERP에서 처리
- 하지만 카톡/문자/사진 발주를 다시 ERP에 입력하는 수작업이 남아 있음

## 3. 이카운트 조사

지인이 사용하는 프로그램은 이카운트였다.

확인한 점:

- 이카운트는 월 4만 원대의 강력한 범용 ERP
- 회계/세무/영업/재고/구매/판매 등 기능이 넓음
- 지인은 전체 기능 중 일부만 사용
- 주로 거래처/품목/단가 저장, 판매 입력, 거래명세서 출력, 판매조회에 사용

전략 변화:

- 이카운트 전체와 정면 경쟁하지 않는다.
- 중간 납품업자의 실제 업무 순서에 맞춘 좁고 깊은 웹 ERP를 목표로 한다.

## 4. 친구 통화에서 확인된 업무 흐름

친구는 중간 납품업자에 가깝다.

업무 흐름:

```text
식당/거래처 발주
→ 친구가 주문 취합
→ 도매상/시장/공급처에 발주
→ 물건 확보
→ 거래처별 납품 준비
→ 거래명세서 발행
→ 납품
→ 미수금/입금 확인
→ 세금계산서/월말 정산
```

중요 발견:

- 카톡 발주가 자동으로 ERP에 들어가는 구조가 아님
- 친구가 발주 내용을 직접 다시 입력함
- 사진으로 발주를 보내는 거래처도 있음
- 여러 거래처 주문을 품목별로 합산하는 일이 있음
- 기존 ERP는 저장/출력에는 좋지만 발주 취합 전 단계가 약함

## 5. 제품명

가칭:

- 오더모아

의미:

- 여러 거래처의 주문을 모은다.
- 모은 주문을 도매상 발주, 거래처별 납품, 거래명세서, 정산으로 이어준다.

주의:

- `오더모아`라는 법인명이 검색 결과에 존재한다.
- 내부 가칭으로 사용한다.
- 외부 공개 전 상표/도메인/앱 이름 확인이 필요하다.
