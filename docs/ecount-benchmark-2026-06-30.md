# 이카운트 벤치마크 메모

작성일: 2026-06-30  
작성 주체: Codex  
근거: 사용자 제공 이카운트 캡처 3장, 실사용 ERP 판매조회 엑셀(파일명에 실상호 포함 — 본 문서에선 `[실상호] 이카운트.xlsx`로 표기), 사용자 통화/관찰 메모

> 주의: 본 문서는 제품 설계 참고용이다. 실제 거래처명·전화번호·사업자번호 등 민감정보는 제품 문서/샘플 데이터에 그대로 옮기지 않는다. 캡처와 엑셀은 기능 구조를 이해하기 위한 참고 자료로만 사용한다.

---

## 1. 결론

이카운트는 전체 ERP로는 오더모아가 단기간에 따라갈 수 없는 수준이다. 따라서 오더모아의 목표는 **이카운트 전체 대체**가 아니라, 친구가 실제로 쓰는 아주 좁은 구간을 더 쉽게 만드는 것이다.

오더모아가 이겨야 할 구간:

> 카톡/문자 원문 발주 → 품목/수량/단위/단가 정제 → 거래처별 판매가 적용 → 예상 마진 확인 → 품목별 합산표 → 거래명세서 미리보기/인쇄

현재 친구가 이카운트를 쓰는 이유는 많은 기능 때문이라기보다 다음 3가지로 보인다.

1. 거래처/품목/단가가 저장되어 있다.
2. 입력하면 거래명세서가 바로 나온다.
3. 판매조회/인쇄/불러온 전표가 이어져 기록이 남는다.

오더모아는 여기에 **카톡 발주 원문 가공**을 붙여야 차별점이 생긴다.

---

## 2. 제공 엑셀에서 확인한 구조

파일: 실사용 ERP 판매조회 엑셀 (`D:\프로젝트폴더\ERP-1\[실상호] 이카운트.xlsx` — 파일명에 실상호 포함, 민감정보로 취급해 본 문서엔 일반화만 기재)

시트:

- `판매조회`

컬럼:

- `일자-No.`
- `거래처명`
- `품목명(요약)`
- `금액합계`
- `거래유형명`
- `창고명`
- `회계반영여부`
- `인쇄`
- `불러온전표`

요약 통계:

- 행 수: 191건
- 기간: 2026-06-01 ~ 2026-06-30 중심
- 거래처 수: 약 13곳
- 총 금액합계: 약 39,853,015원
- 건당 평균: 약 208,655원
- 건당 중앙값: 약 150,250원
- 일별 거래 건수는 대체로 5~9건 수준

의미:

- 친구 업무는 대량 거래처 수보다는 **반복 거래처 + 반복 품목 + 반복 단가** 구조다.
- 따라서 1차 MVP는 복잡한 ERP보다 **반복 입력을 줄이는 거래처별 단가/품목 매칭**이 더 중요하다.
- 판매조회 화면은 “기록 보관”보다 “인쇄/전표 확인으로 바로 이어지는 업무 허브” 역할을 한다.

## 3. 캡처에서 확인한 이카운트 사용면

### 3.1 판매조회

보이는 요소:

- 날짜-No.
- 거래처명
- 품목명 요약
- 금액합계
- 거래유형명
- 창고명
- 인쇄
- 불러온전표 조회

오더모아 반영:

- 대시보드 또는 주문목록에 `거래처 / 요약품목 / 금액 / 상태 / 명세서`가 보여야 한다.
- 주문이 저장되면 바로 거래명세서 미리보기로 이어져야 한다.
- “오늘 주문”과 “최근 주문”은 모바일에서도 빠르게 들어가야 한다.

### 3.2 불러온 전표

보이는 요소:

- 품목코드
- 품목명
- 규격
- 수량

오더모아 반영:

- 파싱 결과 화면은 단순 텍스트가 아니라, 이카운트의 전표처럼 **품목별 라인 표**가 되어야 한다.
- 품목명/수량/단위/단가를 즉시 수정할 수 있어야 한다.
- 미매칭 품목은 “확정 불가”가 맞다.

### 3.3 거래명세서

보이는 요소:

- 공급자/거래처 정보
- 일련번호
- 금액 한글 표기
- 품목명/규격
- 수량
- 단가
- 공급가액
- 부가세
- 합계
- 인쇄/Email/Excel
- 같은 명세서가 한 페이지에 2장 형태로 출력

오더모아 반영:

- 1차는 브라우저 인쇄 가능한 거래명세서 미리보기면 충분하다.
- 다만 현재 HTML 데모보다 실제 거래명세서 양식은 더 촘촘하고 업무 문서답게 다듬어야 한다.
- 부가세/VAT는 당장 자동 계산하지 않더라도, 명세서에는 “공급가 합계”와 “VAT 미적용/후순위”가 분명해야 한다.
- 장기적으로는 `공급가 / VAT / 합계` 구조를 열어둘 필요가 있다.

### 3.4 세금계산서 화면

보이는 요소:

- 전송대기, 결과대기, 전송완료, 오류, 미발행 등 상태
- 발행/발행취소/Email/인쇄/Excel

오더모아 반영:

- 1차에서 홈택스/전자세금계산서 직접 발행은 하지 않는다.
- 다만 월말 정산/세금계산서 발행 금액 확인은 후순위 후보로 유지한다.

## 4. 기능 우선순위 보정

기존 우선순위:

1. 샘플 데이터
2. 거래처/품목/단가 빠른 등록
3. 발주 붙여넣기
4. 파싱 결과 수정
5. 품목별 합산표
6. 거래처별 주문표
7. 거래명세서 미리보기

보정 후:

1. 샘플 데이터
2. 거래처/품목/거래처별 판매단가 빠른 등록
3. 카톡/문자 발주 붙여넣기
4. 파싱 결과 수정
5. 거래처별 판매가 자동 적용
6. 품목별 합산표
7. 거래처별 주문표
8. 거래명세서 미리보기/인쇄
9. 예상 마진 표시(매입단가가 있는 경우)

핵심 변화:

- 단가 관리는 단순 부가 기능이 아니라 MVP 핵심이다.
- 마진은 1차 정산 기능이 아니라 **예상 마진 표시** 수준으로 먼저 둔다.
- 정확한 회계/세무 마진이 아니라, 사장님이 “이 주문이 대략 얼마나 남는지” 보는 용도다.

---

## 5. 마진 기능의 1차 범위

마진을 정확히 하려면 매입처, 매입일, 재고, 실제 원가, 세금까지 엮인다. 이건 1차에 너무 크다.

따라서 1차는 다음처럼 제한한다.

### 포함

- 품목에 `기준 매입단가` 선택 입력
- 거래처별 `판매단가`
- 주문 라인별 예상 마진:
  - `예상 마진 = (판매단가 - 기준 매입단가) × 수량`
- 주문 전체 예상 마진:
  - 라인별 예상 마진 합
- 매입단가가 없으면 마진은 `-` 또는 `매입단가 없음`으로 표시

### 제외

- 실제 매입처별 원가
- 매입일별 원가 변동
- 재고 평가
- 세금 포함 순마진
- 정확한 회계 손익

화면 문구:

> 예상 마진은 기준 매입단가 기준 참고값입니다. 실제 정산 금액과 다를 수 있습니다.

## 6. 최종 TASK 전에 반영할 설계 수정

필수 반영:

- 파싱 결과 화면에 `단가` 직접 수정 입력이 필요하다.
- 파싱 결과 화면에 `금액` 자동계산이 필요하다.
- 거래처별 단가가 없으면 0원 경고만 보여주는 것이 아니라, 바로 단가를 입력하고 저장할 수 있어야 한다.
- 거래명세서 화면은 실제 업무 문서처럼 더 촘촘해야 한다.
- 주문목록은 이카운트 판매조회처럼 `날짜 / 거래처 / 품목요약 / 금액 / 명세서`가 보여야 한다.

권장 반영:

- 품목별 합산표에 예상 매출/예상 마진 컬럼을 선택 표시한다.
- 거래처별 주문표에 예상 마진 합계를 선택 표시한다.
- 샘플 데이터에 기준 매입단가를 추가한다.

보류:

- 전자세금계산서 직접 발행
- PDF 파일 생성
- 이카운트 연동
- 카카오톡 자동 읽기
- OCR 자동 인식

## 7. 이카운트 접속 관련 판단

현재 제공된 캡처와 엑셀만으로도 MVP 보정에는 충분한 단서가 있다.  
웹 아이디/비밀번호를 직접 받아 접속하는 것은 다음 조건일 때만 고려한다.

- 사용자가 명확히 허락한다.
- 접속 목적이 화면 구조 관찰로 한정된다.
- 비밀번호는 문서/코드/로그에 저장하지 않는다.
- 거래처명/전화/사업자번호 등 민감정보는 제품 문서에 복사하지 않는다.
- 가능하면 사용자가 옆에서 화면을 열어주고, Codex는 관찰/정리만 한다.

현재 단계에서는 직접 접속보다 **캡처 + 엑셀 + 사용자 설명**으로 충분하다.

## 8. 한 줄 제품 방향 보정

기존:

> 카톡/문자 발주를 붙여넣으면 거래처별 주문표와 품목별 합산표가 만들어지는 도구

보정:

> 카톡/문자 발주를 붙여넣으면 품목·수량·단가가 정제되고, 거래처별 판매가와 예상 마진을 확인한 뒤 합산표와 거래명세서까지 바로 만드는 납품업자용 웹 ERP
