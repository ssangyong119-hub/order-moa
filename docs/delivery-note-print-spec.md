# 오더모아 거래명세서 인쇄 구현 기준

작성일: 2026-06-30
작성 주체: Claude (단위 5 — 거래명세서 인쇄 기준)
근거 문서: `docs/ecount-benchmark-2026-06-30.md`(§3.3), `docs/function-specification.md`(F13), `docs/screen-specification.md`(S12), `docs/db-schema-definition.md`(delivery_notes)

> 본 문서는 거래명세서 **미리보기/인쇄 화면**의 구현 기준이다. 실거래처명·사업자번호·전화 등 민감정보는 **샘플에서 가짜값 또는 공란**으로만 둔다. 코드/SQL은 포함하지 않는다. 이카운트 캡처는 **구조 관찰**용으로만 참고했다(원본 미첨부·미커밋).

---

## 1. 목적과 범위

- 거래처에 **납품 명세를 인쇄/전달**할 수 있는 업무 문서 수준의 미리보기 화면.
- **1차 MVP 범위**: 브라우저 인쇄(`window.print`) 우선, A4 1장 정돈 출력, **VAT 계산 없음**.
- **후순위/제외**: PDF 파일 생성, 전자세금계산서 발행, `note_number` 자동 채번, 이메일/엑셀 전송.

> 핵심: 현재 HTML 데모보다 **더 촘촘하고 실제 거래명세서다운** 양식. 빈 여백을 줄이고 공급자/거래처 블록과 라인 표를 정렬한다.

---

## 2. 이카운트 거래명세서에서 참고한 구조 (관찰 일반화)

원본 캡처에서 **구조만** 관찰했다(실값 미반영).

- 상단: 공급자 정보 / 거래처(공급받는 자) 정보 — **좌우 2블록**
- 일련번호, 일자
- 금액 한글 표기(예: "금 일십오만원정")
- 라인 표: 품목명 / 규격 / 수량 / 단가 / 공급가액 (이카운트는 부가세 열도 있음)
- 합계: 공급가액 합계 / 부가세 / 합계 (오더모아 1차는 **공급가 합계만**)
- 같은 명세서를 **한 페이지에 2부**(보관용/거래처용)로 출력하는 형태

---

## 3. 1차 MVP 거래명세서 레이아웃

### 3.1 상단 — 공급자 정보 블록 (좌)

| 항목 | 1차 처리 |
|---|---|
| 상호(회사명) | `companies.name` |
| 사업자번호 | `companies.business_number`(없으면 공란). **샘플은 가짜값/공란** |
| 대표자/주소/전화 | 1차 선택 — 회사 정보에 있으면 표시, 없으면 공란(스키마 강제 안 함) |
| 문서 제목 | "거래명세서" |

### 3.2 상단 — 거래처 정보 블록 (우)

| 항목 | 1차 처리 |
|---|---|
| 거래처명 | `customers.name` |
| 전화/주소 | `customers.phone`/`address`(없으면 공란) |
| 사업자번호 | 1차 미보유 가능 → 공란 |

### 3.3 문서 메타

- **일자**: `orders.order_date`
- **일련번호**: 1차는 **자동 채번 안 함**(공란 또는 주문 id 일부 표시). `delivery_notes.note_number` 채번은 후순위(D).
- **금액 한글 표기**: 선택(있으면 신뢰도↑). 1차 후보.

### 3.4 라인 표

| 열 | 소스 | 비고 |
|---|---|---|
| No | 행 순번 | |
| 품목명 | `order_items.product_id`→`products.name` | 규격 포함 가능(샘플 §10.3) |
| 규격 | (1차) 품목명에 포함 / `unit` 보조 | 별도 컬럼은 2차 |
| 수량 | `order_items.quantity` | numeric |
| 단위 | `order_items.unit` | 입력 단위 그대로 |
| 단가 | `order_items.unit_price` | KRW integer |
| 공급가액 | `order_items.amount` = `round(수량×단가)` | 생성값 |

- 빈 행을 일정 수 채워 **표 높이를 고정**(업무 문서 느낌, 선택).

### 3.5 합계 영역

- **공급가 합계** = Σ `order_items.amount` (합산 후 반올림 없음)
- **VAT**: 1차 **계산·표기 없음**. (열을 둘 경우 "VAT 미적용" 명시, 0 또는 공란)
- 합계 = 공급가 합계 (VAT 없으므로 동일)

> `products.tax_type`은 보존하되 1차 명세서 계산에 쓰지 않는다(2차).

## 4. 인쇄 동작 기준

- **브라우저 인쇄 우선**: `window.print()` + `@media print` CSS.
- **A4 기준**: `@page { size: A4; margin: 10mm; }` 류. 한 페이지에 들어가도록 폰트/여백 조정.
- **인쇄 시 숨김**: 앱 네비게이션/버튼/배경색 등은 `@media print`에서 숨기고, 명세서 영역만 출력.
- **색상**: 인쇄는 기본 흑백 가독성 우선(배경 컬러 의존 금지).
- **PDF**: 후순위. 1차는 "브라우저 인쇄 → PDF로 저장"을 사용자가 직접 할 수 있다는 안내로 갈음.

### 4.1 1장 2부 출력 (보관용/거래처용) — 검토

- **가능성**: A4 한 장에 동일 명세서를 위/아래 2부 배치(이카운트 방식). 절취선 표시.
- **1차 판단**: **선택 옵션**. 기본은 1부. 2부 토글은 후보(구현 단순하면 포함, 레이아웃 부담되면 2차).
- 2부 시 각 부 하단에 "공급자 보관용 / 공급받는자 보관용" 라벨.

---

## 5. 모바일 고려

- 모바일은 **미리보기 중심**. 실제 인쇄/출력은 **PC + 프린터 권장**(screen-spec §12, Q3 확정).
- 모바일에서 표가 넘치면 가로 스크롤 미리보기. 인쇄 버튼은 보이되 "PC 권장" 안내.

---

## 6. 예외/상태

| 상황 | 처리 |
|---|---|
| 품목 0줄 | 명세서 생성 경고, 인쇄 차단 |
| 단가 미등록 라인 | 0원 + 경고 표시(인쇄에도 0원으로 나감 — 사용자 인지) |
| 회사/거래처 정보 일부 공란 | 공란 그대로 출력(강제 입력 아님) |
| 사업자번호 없음 | 공란 |

---

## 7. 샘플/민감정보 규칙

- 공급자/거래처 사업자번호·전화·주소는 **샘플에서 가짜값 또는 공란**.
- 실거래처명/실사업자번호/실주소를 문서·샘플에 넣지 않는다.
- 이카운트 원본 캡처는 **커밋하지 않는다**. 민감정보 가린 이미지를 사용자가 `data/references/ecount/`에 넣은 경우에만 커밋 후보로 검토.
